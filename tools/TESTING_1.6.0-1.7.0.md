# Что нажимать в Home Assistant: проверка версий 1.6.0, 1.6.1, 1.6.2 и 1.7.0

Пошаговая инструкция для интеграции **ReglerPro Controller**. Каждая версия описана отдельным
разделом: что изменилось, какие кнопки нажимать, что должно получиться и что прислать, если
получилось иначе.

## Как пользоваться

Версии накопительные: каждая следующая содержит все изменения предыдущих. Поэтому достаточно
**одной установки самой новой сборки (1.7.1)**: на ней проверяются все четыре раздела. Отдельные
старые сборки для этого не нужны.

| Раздел | Версия | Что проверяется |
|---|---|---|
| A | 1.6.0 | загрузка, перезагрузка, отключение записи, службы без записи, серия быстрых записей |
| B | 1.6.1 | диапазоны чисел, состояние «в сети», применение профиля котла и сообщение о проблемах |
| C | 1.6.2 | применение профиля климата при выключенном и включённом климате |
| D | 1.7.0 | добавление интеграции: проверка входа, выбор дома, повторная авторизация |

> **Особенность сборки 1.7.1.** В ней часть числовых полей котла может быть «Недоступна», если
> приложение ReglerPro для вашего котла их не показывает (например, `Fan (min)`). Это не ошибка.
> Для проверок ниже выбирайте поля, которые доступны.

Названия кнопок и полей указаны по-английски (так они записаны в переводах). В русском интерфейсе
они по смыслу те же. Если какой-то пункт называется иначе, отметьте это в отчёте.

Ориентировочное время: 40–60 минут на все четыре раздела.

---

## Подготовка (один раз)

1. **Резервная копия.** *Настройки → Система → Резервные копии → Создать резервную копию*.
2. **Файлы.** Замените файлы из `kotel_1.7.1.zip` и выполните
   `python scripts/merge_translations_1_4_6.py`.
3. **Перезапуск.** *Настройки → Система*, значок питания в правом верхнем углу →
   **Перезапустить Home Assistant**.
4. **Подробный журнал.** *Настройки → Устройства и службы* → карточка **ReglerPro Controller** →
   **⋮ → Включить отладочное логирование**. Если такого пункта нет, пропустите (журнал можно взять и
   без него).
5. **Запишите время начала** (часы сервера Home Assistant): оно нужно, чтобы найти события в журнале.

### Где что находится

| Что нужно | Куда нажимать |
|---|---|
| Устройство контроллера | карточка ReglerPro → ссылка «N устройств» → контроллер |
| Поля настроек котла | страница устройства → блок **Конфигурация** |
| Кнопки и списки профилей | страница устройства → блок **Управление** |
| Показания и атрибуты | **Инструменты разработчика → Состояния** (поле «Фильтр сущностей») |
| Вызов служб | **Инструменты разработчика → Действия** |
| Журнал | **Настройки → Система → Журналы** |
| Диагностика | рядом с записью **⋮ → Скачать диагностику** |

## Раздел A. Версия 1.6.0

**Что изменилось.** Внутренняя перестройка: данные записи хранятся в `runtime_data`, службы
регистрируются при загрузке интеграции, у платформ записи включено последовательное выполнение.
Для пользователя ничего не должно измениться, кроме понятной ошибки служб, когда запись не загружена.

### A1. Загрузка

1. *Настройки → Устройства и службы* → карточка **ReglerPro Controller**.
2. Ожидается: на карточке нет красных сообщений («Не удалось загрузить», «Ошибка настройки»).
3. Откройте устройство контроллера: на странице есть блоки **Управление**, **Датчики**,
   **Конфигурация**, **Диагностика**, сущности показывают значения.

### A2. Перезагрузка и отключение записи

1. На карточке интеграции нажмите **⋮ → Перезагрузить**. Ожидается: через несколько секунд запись снова
   «Загружена», сущности вернулись.
2. Нажмите **⋮ → Отключить**. Ожидается: сущности исчезают (становятся «Недоступно» или пропадают).
3. Не включайте запись обратно, пока не выполните A3.

### A3. Службы без загруженной записи

Запись отключена (A2).

1. **Инструменты разработчика → Действия**.
2. В поле «Действие» выберите **`kotel.list_profiles`** и нажмите **Выполнить действие**.
   Ожидается: ответ с пустым списком устройств (`devices: {}`).
3. Выберите **`kotel.save_profile`**, в поле имени введите любой текст и выполните.
   Ожидается: понятная ошибка вида «Контроллеры Kotel не найдены», а не «Служба не найдена»
   и не длинный технический текст.
4. Включите запись обратно: **Настройки → Устройства и службы → ReglerPro → ⋮ → Включить**.
   Ожидается: запись загружена, сущности вернулись.

### A4. Серия быстрых записей

Проверяет, что команды одной платформы выполняются по очереди.

1. На странице контроллера, блок **Конфигурация**, выберите безопасное доступное поле, например
   **Pump temperature**, и запомните его текущее значение.
2. **Инструменты разработчика → Действия** → действие **«Число: Задать значение»**
   (`number.set_value`) → выберите это поле → в «Значение» впишите **текущее значение** (так ничего не
   изменится).
3. Нажмите **Выполнить действие** три раза подряд, как можно быстрее.
4. Ожидается: ошибок нет. В журнале (если включено отладочное логирование) три строки
   `POST ... | action=<параметр>` идут одна за другой, а не вперемешку.

### A5. Окно «Добавить датчик»

1. На карточке интеграции нажмите **Настроить**.
2. Ожидается: открывается меню с пунктами (в том числе **Register a temperature sensor** и **Servers**).
3. Выберите **Register a temperature sensor** и сразу закройте окно крестиком: **подтверждение не
   отмечайте**, иначе на сервере создастся новый идентификатор датчика.

### A6. Диагностика

Рядом с записью **⋮ → Скачать диагностику**. Ожидается: файл скачивается. Откройте его и убедитесь, что
в блоке `entry.data` логин, пароль и номер дома заменены на `***`, а в блоке `coordinator.devices` ключи
имеют вид `<device-1>`.

**Что прислать при проблеме:** точный текст ошибки, время, журнал (раздел «Сбор данных» ниже).

## Раздел B. Версия 1.6.1

**Что изменилось.** Сверка с приложением ReglerPro: диапазоны двух параметров шнека, правила «в сети»
для датчика (1800 с) и контроллера (запас 600 с после обрыва), изоляция ошибки одного устройства;
повторная проверка записи профиля и подробное сообщение о том, какое значение не подтвердилось.

### B1. Диапазоны чисел шнека

1. **Инструменты разработчика → Состояния**.
2. В фильтре введите **auger** (или **шнек**, если у вас русский интерфейс).
3. У сущностей **Auger run (heating)** и **Auger run (maintenance)** в атрибутах должно быть
   `max: 600`, у **Auger interval (heating)** — `max: 600`, у **Auger interval (maintenance)** —
   `max: 900`.
4. Если у вашего котла шнека нет (не «авто»-котёл), эти сущности «Недоступны»: этот пункт пропустите и
   отметьте в отчёте.

### B2. Состояние «в сети»

1. **Инструменты разработчика → Состояния** → фильтр **connection**.
2. Откройте сущность **Connection status** и посмотрите атрибуты: должны быть `mqtt_online` и
   `offline_seconds`; состояние — `online`.
3. Фильтр **time** или имя датчика температуры: у сущности датчика в атрибутах `last_update_seconds` и
   `online: true`.

### B3. Применение профиля котла (основная проверка версии)

1. На странице контроллера, блок **Управление**, в поле **New boiler profile name** введите `Тест`
   и нажмите Enter.
2. Нажмите **Save boiler profile**. В списке **Boiler profile** появится `Тест`.
3. Измените безопасный параметр (например **Pump temperature** на 1 °C) и запомните исходное значение.
4. В списке **Boiler profile** выберите `Тест` и нажмите **Apply boiler profile**.
5. Ожидается: без ошибки, параметр вернулся к исходному значению.
6. Если появилось красное сообщение («Не удалось выполнить действие button/press…»), **скопируйте его
   целиком**. В нём теперь названы значения вида `boiler.<параметр> (ожидалось X, получено Y)` и
   указано, сколько значений записано повторно.
7. В журнале уровня `info`/`debug` ищите строку «**Значения подтверждены через get_big_contr_check**»:
   она означает, что основной опрос отстал, а запрос проверки подтвердил запись.

### B4. Пробный запуск профиля (ничего не записывает)

1. **Инструменты разработчика → Действия** → **`kotel.apply_profile`**.
2. Сначала в форме выберите контроллер в блоке «Цели» (**Выбрать устройство**), затем нажмите
   **Перейти в режим YAML** и поправьте поля:

   ```yaml
   action: kotel.apply_profile
   target:
     device_id: <остаётся тот, что выбрали>
   data:
     name: "Тест"
     kind: boiler
     dry_run: true
   ```
3. Нажмите **Выполнить действие**. Ожидается ответ со списками `changes` (что будет записано),
   `skipped`, `ok: true`. Если профиль совпадает с текущими значениями, `changes` пуст.

**Что прислать:** текст сообщения (шаг B3.6) или ответ службы целиком (замените `device_id` метками).

## Раздел C. Версия 1.6.2

**Что изменилось.** Значения профиля климата (режим, температура, расписание, датчик) не записываются,
пока климат-контроль выключен. В приложении ReglerPro при выключенном климате доступна только кнопка
«Включить». Значения котла применяются всегда.

> Все шаги ниже включают и выключают климат-контроль контроллера. Делайте их, когда это безопасно для
> отопления, и в конце верните прежнее состояние.

### C1. Подготовка профиля

1. Убедитесь, что **Thermostat** включён (не в состоянии «Выкл.»).
2. В блоке **Управление** введите `Климат тест` в поле **New climate profile name**, нажмите Enter.
3. Нажмите **Save climate profile**. В списке **Climate profile** появится `Климат тест`.

### C2. Климат выключен: применение запрещено

1. Откройте карточку **Thermostat** и выключите её (кнопка питания или режим «Выкл.»). Подождите около
   30 секунд, чтобы состояние обновилось.
2. В списке **Climate profile** выберите `Климат тест` и нажмите **Apply climate profile**.
3. Ожидается красное сообщение с текстом **«климат-контроль выключен: включите его и примените профиль
   снова»**. Режим и температура термостата **не должны** измениться.

### C3. Пробный запуск при выключенном климате

В **Инструменты разработчика → Действия** вызовите `kotel.apply_profile` (как в B4) с

```yaml
data:
  name: "Климат тест"
  kind: climate
  dry_run: true
```

Ожидается: в ответе значения климата лежат в `skipped` с причиной про выключенный климат, `failed` пуст,
`ok: true`.

### C4. Климат включён: применение проходит

1. Включите **Thermostat** (лучше кнопкой питания, чтобы не менять режим). Подождите около 30 секунд.
2. Нажмите **Apply climate profile** для `Климат тест`.
3. Ожидается: без ошибки (значения уже совпадают или записываются полностью).

### C5. Необязательно: принудительное применение

Выключите климат и вызовите `kotel.apply_profile` с `force: true` (без `dry_run`): значения климата
**будут записаны**, проверка отключена. Выполняйте только если готовы к этому; затем верните климат
в нужное состояние.

### C6. Завершение

Верните термостат в нужное вам состояние и удалите тестовый профиль: выберите его в списке и нажмите
**Delete climate profile**.

**Что прислать при проблеме:** текст сообщения, ответ службы, состояние **Thermostat** до и после.

## Раздел D. Версия 1.7.0

**Что изменилось.** Окно добавления интеграции проверяет вход запросом `login_user`, показывает дома
учётной записи и сверяет введённый номер дома со списком. Повторная авторизация проверяет только логин
и пароль.

Дубль записи создать нельзя (он отклоняется до создания), поэтому проверки безопасны. Подробный журнал для
этого раздела удобнее включить способом из раздела «Сбор данных» (через `logger.set_level`), потому что
запись ещё не создаётся.

### D1. Неверный пароль

1. **Настройки → Устройства и службы → «+ Добавить интеграцию»** → поиск **ReglerPro** → выбрать.
2. Введите верные сервер и логин, **неверный пароль**, поле **Home ID** оставьте пустым → **Отправить**.
3. Ожидается ошибка: «Неверный логин или пароль» или «Сервер отклонил вход: …».
4. **Скопируйте текст целиком.** Особенно важно, если после слов «Сервер отклонил вход:» есть пояснение
   сервера: по нему можно добавить точное распознавание.

### D2. Верный вход, Home ID пустой

1. Введите верные данные, **Home ID оставьте пустым** → **Отправить**.
2. Если у вас один дом: интеграция сама проверит устройства и ответит **«уже настроено»**. Это значит,
   что вход и список домов сработали.
3. Если домов несколько: откроется шаг **«Выбор дома»** со списком «название (номер)». Выберите дом: ожидается
   «уже настроено».

### D3. Номер дома, которого нет среди ваших домов

1. Введите верные данные и в **Home ID** впишите выдуманный номер, например `1234567890123`.
2. Ожидается: «Этого номера дома нет среди домов учётной записи: …» со списком ваших домов.

### D4. Список домов недоступен (только если встретится)

Если вместо шага выбора дома появилась ошибка «Список домов недоступен. Введите номер дома», введите номер
дома вручную: интеграция должна продолжить как раньше. Отметьте это в отчёте и приложите вывод
`kotel_probe.py homes` (см. `DIAGNOSTICS.md`).

### D5. Закрытие окна

Закройте окно крестиком. Никаких новых записей на карточке интеграции появиться не должно.

### D6. Повторная авторизация (необязательно, для опытных)

Нужен доступ к файлам Home Assistant. **Файл `core.config_entries` хранит пароли открытым текстом:
не отправляйте его никому.**

1. Остановите Home Assistant (*Настройки → Система → питание → Остановить*).
2. Сделайте копию `/config/.storage/core.config_entries`.
3. В записи с `"domain": "kotel"` замените значение `"password"` на неверное.
4. Запустите Home Assistant.
5. Ожидается уведомление **«Требуется повторная авторизация»** для ReglerPro (в колокольчике или на
   карточке интеграции кнопка **«Перенастроить»**).
6. Введите **неверный** пароль: ошибка. Введите **верный**: сообщение об успехе, запись **перезагружается
   сама** (без перезапуска Home Assistant), сущности возвращаются.
7. Если после верного пароля данные остались недоступными, приложите журнал и диагностику.

**Что прислать:** тексты всех ошибок по шагам D1–D4 и время.

## Сбор данных

### Журнал

* **Если запись есть:** карточка ReglerPro → **⋮ → Включить отладочное логирование**, воспроизведите
  шаги, затем **⋮ → Отключить отладочное логирование**. Файл журнала скачается сам.
* **Если записи ещё нет (раздел D):** **Инструменты разработчика → Действия** → `logger.set_level`
  в режиме YAML:

  ```yaml
  action: logger.set_level
  data:
    custom_components.kotel: debug
  ```

  После проверки верните уровень: `custom_components.kotel: warning`. Журнал берите в
  **Настройки → Система → Журналы → Загрузить полный журнал**.

### Диагностика

Рядом с записью **⋮ → Скачать диагностику**.

### Очистка перед отправкой

Номер дома и идентификаторы устройств нельзя отправлять открытыми. Очистите журнал скриптом
`tools/scrub_log.py` и проверьте оба файла поиском: логин, пароль, номер дома, 13-значные
идентификаторы, названия домов не должны находиться. Подробности — в `DIAGNOSTICS.md`, раздел 9.
