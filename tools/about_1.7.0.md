Версия 1.7.0 готова: окно подключения теперь проверяет вход через `login_user` и предлагает дома из `get_data_sets`. Все 236 тестов проходят, включая каждый файл отдельно в чистой установке. Но форматы ответов этих двух запросов я взял из кода приложения (`reglog.js`, `sets.js`), на живом сервере они не проверялись.

Распакуйте `kotel_1.7.0.zip` поверх репозитория с заменой файлов (33 файла) и слейте переводы: `python scripts/merge_translations_1_4_6.py`. Скрипт добавит новые строки и обновит текст ошибки «Введите номер дома».

## Как теперь работает добавление интеграции

1. **Первый шаг:** сервер, логин и пароль. Номер дома необязателен.
2. **Проверка входа** запросом `login_user`, как в приложении. Если сервер отклоняет вход и поясняет причину, текст показывается в ошибке. Он очищается от разметки и от логина с паролем. Если пояснения нет, остаётся прежнее «Неверный логин или пароль».
3. **Дома** берутся запросом `get_data_sets`:
   - один дом выбирается сам;
   - несколько домов дают список «название (номер)»;
   - введённый вручную номер должен быть среди ваших домов, иначе ошибка «этого номера нет среди домов учётной записи» со списком ваших домов;
   - если домов нет, сообщение «У этой учётной записи нет домов»;
   - если список домов получить не удалось, остаётся прежнее поле для ручного ввода номера.
4. **Повторная авторизация** проверяет только логин и пароль, без запроса устройств.

Название записи теперь содержит название дома. Данные записи (`url`, `login`, `password`, `home_id`) не изменились, существующие записи продолжают работать.

Проверка принадлежности дома закрывает находку 74 со стороны интеграции: нельзя случайно или намеренно подключить чужой номер через окно настроек. Сервер по-прежнему не проверяет членство при `get_all_dev`, это его проблема. На ваш сценарий «образец профиля для пользователей с другим оборудованием» это не влияет: профили от номера дома не зависят.

## Что неизвестно и нужно проверить

- Что `login_user` отвечает на неверный пароль и что кладёт в поле `text`.
- Совпадают ли номера в списке домов с номером, который принимает `get_all_dev`. В коде приложения это один и тот же номер, но после выбора дома интеграция всё равно проверит устройства: при расхождении будет «Нет устройств».
- Номера домов бывают отрицательными (в `script.js` есть примеры вида `-1002211493629`). Я это учёл, номера не проверяются на «только цифры».

Если ответы окажутся другими, интеграция не сломается: список домов вернётся к ручному вводу, а ответ `login_user` другого вида даст «неожиданный ответ» с выдержкой из него. Пришлите выдержку, я добавлю точные признаки.

## Что проверить на живом Home Assistant

Для проверки можно добавить запись заново, например второй раз для того же дома, и затем отменить: дубль отклоняется до создания записи.
1. Неверный пароль: какой текст показывает сервер.
2. Верный вход без номера дома: один дом выбирается сам, несколько дают список.
3. Номер дома, которого нет среди ваших домов.
4. Повторная авторизация с верным и неверным паролем.
5. По желанию: в журнале уровня `debug` для `custom_components.kotel.api` виден вид ответов `login_user` и `get_data_sets`.
