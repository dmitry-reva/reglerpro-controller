# Стандарт переводов и именования сущностей

Документ фиксирует единые правила для интерфейса, сущностей, служб и
документации ReglerPro Controller. Цель — чтобы русский и английский
интерфейсы описывали одно и то же одинаковыми терминами, а `entity_id`
оставались стабильными.

## 1. Где лежат переводы

| Файл | Назначение |
|---|---|
| `custom_components/kotel/strings.json` | источник (английский), его читает Home Assistant |
| `custom_components/kotel/translations/en.json` | английский перевод, должен совпадать со `strings.json` |
| `custom_components/kotel/translations/ru.json` | русский перевод |
| `custom_components/kotel/services.yaml` | только схема служб: поля, селекторы, значения по умолчанию |

Названия и описания служб и полей — в `strings.json` / `translations/*.json`
(поддержка с Home Assistant 2023.8). В `services.yaml` их быть не должно,
иначе перевод не применится.

## 2. Сущности

### 2.1. Обязательные правила

1. У каждой сущности есть `unique_id` формата
   `kotel_<id_name>_<суффикс>`; суффикс **никогда не меняется**.
2. `has_entity_name = True` (базовый класс `KotelEntity`).
3. Название сущности задаётся только через `translation_key`, без русского
   текста в Python.
4. `translation_key` — английский `snake_case`, стабильный. Менять можно
   текст перевода, но не ключ.
5. В названии сущности нет имени устройства: его добавляет Home Assistant.
6. Один термин — одно понятие (см. глоссарий). Нельзя в одном месте писать
   «уставка», а в другом «целевая» для одного и того же параметра.

### 2.2. Шаблон

```json
{
  "entity": {
    "sensor": {
      "water_temperature": {
        "name": "Температура воды"
      }
    },
    "number": {
      "boiler_target_temperature_max": {
        "name": "Уставка температуры (макс.)"
      }
    }
  }
}
```

Для перечислений (`device_class: enum`) переводятся и состояния:

```json
{
  "entity": {
    "sensor": {
      "operating_state": {
        "name": "Состояние работы",
        "state": {
          "Остановлен": "Stopped",
          "Работает": "Running",
          "Розжиг/Угасание": "Ignition/burnout",
          "Неизвестно": "Unknown"
        }
      }
    }
  }
}
```

Состояния `да` / `нет`, `online` / `offline`, `Остановлен` / `Работает` /
`Розжиг/Угасание` и русские названия пресетов **сохранены как значения**:
их используют автоматизации. В английском интерфейсе они отображаются
переводами, но в шаблонах остаются прежними. Переход на стабильные
английские значения — задача версии 2.0 (потребует миграции автоматизаций).

### 2.3. Категории

* `diagnostic` — всё, что нужно для отладки: версия прошивки, аварии, шнек,
  климатические значения, «Диагностика параметров».
* `config` — настройки, которые меняются редко: коррекция, продувка,
  вентилятор, шнек, расписание.
* Без категории — ежедневные сущности: температура, состояние, уставки,
  термостат, профили.

## 3. Службы

Название и описание службы и каждого поля — в `services`:

```json
{
  "services": {
    "apply_profile": {
      "name": "Применить профиль",
      "description": "Записать значения профиля в контроллер.",
      "fields": {
        "name": {
          "name": "Имя профиля",
          "description": "Имя сохранённого профиля."
        }
      }
    }
  }
}
```

`services.yaml` хранит только `target`, `fields`, `selector`, `required`,
`default`, `example`. Селекторы с `label` (например, `boiler` / `climate`)
пока содержат русские подписи — это ограничение фронтенда Home Assistant;
значения (`boiler`, `climate`) стабильны и не переводятся.

## 4. Глоссарий

| Русский | Английский | Не использовать |
|---|---|---|
| котёл | boiler | котёл-автомат (в именах сущностей) |
| контроллер | controller | прибор, устройство (для ReglerPro) |
| климат-контроль | climate control | климат (в значении «термостат») |
| термостат | thermostat | климат |
| уставка температуры | target temperature | задание, установка |
| целевая температура (климата) | climate target temperature | уставка (для климата) |
| температура воды | water temperature | температура теплоносителя (в именах) |
| шнек | auger | шнек-подача |
| интервал шнека | auger interval | пауза шнека |
| время работы шнека | auger run time | работа шнека |
| автореверс | auto-reverse | реверс (без «авто») |
| продувка | purge | обдув |
| время продувки | purge time | длительность продувки |
| интервал продувки | purge interval | пауза продувки |
| угасание | burnout | затухание |
| розжиг | ignition | запуск |
| поддержание | maintenance | удержание |
| нагрев | heating | обогрев |
| охлаждение | cooling | остывание |
| вентилятор | fan | дутьевой вентилятор (в именах) |
| насос | pump | циркуляционный насос (в именах) |
| симистор | triac | тиристор |
| датчик | sensor | сенсор (в текстах для пользователя) |
| профиль | profile | пресет (для профилей) |
| расписание | schedule | таймер, программа |
| период | period | интервал (для расписания) |
| авария | failure | ошибка (для аварии шнека) |
| тревога | alarm | сигнал |
| ошибка датчика | sensor error | неисправность датчика (в именах) |
| статус подключения | connection status | связь, онлайн-статус |

### Правила оформления

* «макс.» и «мин.» — с точкой и только в скобках: `Уставка температуры (макс.)`.
* Не использовать `t°`, `t воды`, `max/min` латиницей в русских названиях.
* Расписание: `Расписание 7/7 (ПН–ВС): П1 — начало`,
  `Расписание 7/7 (ПН–ВС): П1 — температура`.
* Числа: `0,5` в русском тексте, `0.5` в английском.
* Единицы: `°C`, `с`, `мин`, `%` — без точки.
* Названия кнопок — глагол + объект: «Сохранить профиль котла».

## 5. Порядок добавления строки

1. Добавить `translation_key` в код платформы.
2. Добавить `entity.<platform>.<key>.name` в `strings.json` (английский).
3. Повторить в `translations/en.json` и `translations/ru.json`.
4. Для enum — добавить `state` во все три файла (в русском можно повторить
   русские значения, чтобы не было отката на английский).
5. Запустить `python scripts/check_i18n.py`.
6. Обновить [ENTITIES.md](./ENTITIES.md), если появилась новая сущность.

## 6. Проверка

```bash
python scripts/check_i18n.py
```

Скрипт проверяет:

* `strings.json` = `translations/en.json`;
* в `ru.json` нет пропущенных и лишних ключей;
* у каждой сущности есть `name`;
* каждый `translation_key` из Python есть в `strings.json`;
* все службы из `services.py` описаны в переводах.

## 7. Совместимость

* `unique_id` не меняются, поэтому существующие сущности, автоматизации и
  дашборды продолжают работать.
* После включения `has_entity_name` отображаемые имена получают префикс имени
  устройства. `entity_id` в реестре не меняется.
* Значения состояний (`да`/`нет`, русские пресеты) не меняются до 2.0.
* Переводы читаются при старте Home Assistant: после правки
  `translations/*.json` нужен перезапуск.
