## Требования

| Требование | Значение |
|---|---|
| Home Assistant | **2026.3.0 и новее** (нужно для иконки и логотипа из папки `brand/`; без них интеграция работает, но иконка не отображается) |
| Учётная запись | логин и пароль от [app.reglerpro.ru](https://app.reglerpro.ru) с подключённым контроллером |
| Сеть | доступ Home Assistant к `https://app.reglerpro.ru` |
| Внешние Python-зависимости | не требуются |

Интеграция работает через облако производителя: локального управления нет, данные обновляются опросом.

## Установка через HACS

1. HACS → **Интеграции** → меню (три точки) → **Пользовательские репозитории**.
2. Добавьте `https://github.com/dmitry-reva/reglerpro-controller`, категория **Integration**.
3. Найдите **ReglerPro Controller** и нажмите **Скачать**.
4. **Перезапустите Home Assistant.**
5. Перейдите к разделу [Добавление интеграции](#добавление-интеграции).

> С версии 1.4.1 HACS скачивает `kotel.zip` из GitHub Releases
> (`zip_release: true`, `filename: kotel.zip`). Архив собирается
> автоматически workflow `Release zip` и содержит файлы интеграции в корне.
> Если в релизе нет asset `kotel.zip`, установка завершится ошибкой загрузки.

## Ручная установка

1. Скопируйте папку `kotel/` из репозитория (`custom_components/kotel/`) в каталог конфигурации Home Assistant. Результат должен выглядеть так:

   ```
   /config/custom_components/kotel/
   ├── __init__.py
   ├── api.py
   ├── button.py
   ├── climate.py
   ├── config_flow.py
   ├── const.py
   ├── coordinator.py
   ├── diagnostics.py
   ├── entity.py
   ├── manifest.json
   ├── number.py
   ├── params_parser.py
   ├── profiles.py
   ├── select.py
   ├── sensor.py
   ├── services.py
   ├── services.yaml
   ├── strings.json
   ├── switch.py
   ├── text.py
   ├── brand/
   │   ├── icon.png
   │   ├── icon@2x.png
   │   ├── logo.png
   │   └── logo@2x.png
   └── translations/
       ├── en.json
       └── ru.json
   ```

2. Убедитесь, что файлы лежат **непосредственно** в `custom_components/kotel/`, а не во вложенной папке (`kotel/kotel/`).
3. **Перезапустите Home Assistant.**

## Добавление интеграции

1. **Настройки → Устройства и службы → Добавить интеграцию → ReglerPro Controller.**
2. Заполните поля:

   | Поле | Описание | По умолчанию |
   |---|---|---|
   | Адрес сервера | URL облака | `https://app.reglerpro.ru` |
   | Логин | логин учётной записи | — |
   | Пароль | пароль учётной записи | — |
   | ID дома | идентификатор дома; можно оставить пустым | пусто |

3. Если после ввода данных появляется сообщение «Устройства не найдены. Укажите ID дома», введите ID дома. Он передаётся в запросах веб-приложения в поле `userId` (в инструментах разработчика браузера: вкладка *Network*, запрос к `taptop.php`).

   > ⚠️ В запросах веб-приложения логин и пароль передаются открытым текстом. Не публикуйте записи сетевых запросов (HAR) и логи без проверки.

4. После успешного подключения появится устройство для каждого контроллера и датчика.

## Что создаётся

Базовые сенсоры создаются для каждого контроллера. **Диагностические**
сенсоры создаются, только если контроллер отдаёт параметр; если при запуске
контроллер был офлайн, создаются все возможные. Полный каталог — в
[ENTITIES.md](./ENTITIES.md).

В интерфейсе имя сущности — «Имя устройства · Название», например
«Kotel контроллер · Температура воды». `unique_id` не меняется между
версиями, `entity_id` создаётся один раз и зависит от имени устройства.

### Контроллер котла

| Платформа | Сущности |
|---|---|
| `sensor` | температура воды, уставки (max/min), температура шнека, состояние (Остановлен / Работает / Розжиг/Угасание), статус подключения (`online` / `offline`), режим климат-контроля (Нагрев / Охлаждение / Выключен), **активные профили котла и климата** |
| `sensor` (диагностика) | версия прошивки, вентилятор включён, аварии и ошибки (тревога по воде, авария шнека, ошибки датчиков воды и шнека, ошибка симистора), параметры шнека, значения климат-контроля, «Диагностика параметров» |
| `switch` | Старт/Стоп |
| `number` | 11 настроек котла: уставки max/min, температура насоса, коррекция, время и интервал продувки, вентилятор min/max, время угасания, интервалы шнека |
| `number` (расписание) | 48 полей расписания климат-контроля: время начала и температура 4 периодов в 6 наборах (категория «Конфигурация») |
| `climate` | «Термостат»: режимы `Выкл`, `Нагрев`, `Авто`, пресеты расписаний 7/7, 5/2, 4/1/2 |
| `select` | «Датчик климат-контроля», «Профиль котла», «Профиль климата» |
| `text` | «Имя нового профиля котла», «Имя нового профиля климата» |
| `button` | для котла и для климата отдельно: «Сохранить профиль …», «Обновить профиль …», «Применить профиль …», «Отменить применение (котёл)» / «(климат)» |

Бинарные параметры (аварии, ошибки, вентилятор, «Климат: включён» и т. п.) отображаются как **«нет» / «да»**.

### Датчик температуры

| Платформа | Сущности |
|---|---|
| `sensor` | температура; в атрибутах `last_update_seconds` и `online` |

### Службы

`kotel.save_profile`, `apply_profile`, `undo_apply`, `rename_profile`, `delete_profile`, `list_profiles`, `export_profiles`, `import_profiles`, а также отладочная `kotel.send_command`. Профили котла и климата хранятся, выбираются и применяются раздельно (параметр `kind`). Подробности — [PROFILES.md](./PROFILES.md).

## Проверка после установки

1. Откройте устройство контроллера: должны быть сенсоры температуры воды, состояния и статуса подключения.
2. Проверьте сенсор **«Диагностика параметров»** (раздел «Диагностика»): его значение — число разобранных параметров. Если оно равно `0`, смотрите атрибут `params_raw` и [отладку](#отладка).
3. Убедитесь, что статус подключения `online`.
4. Изменение любой уставки (`number`) должно отражаться в облачном приложении, и наоборот: значение в Home Assistant обновляется при следующем опросе.
5. Откройте **Настроить** у интеграции: в меню доступны параметры опроса,
   регистрация датчика температуры, экспорт и импорт профилей, загрузка файла
   и удаление профилей.
6. Проверьте **Скачать диагностику** в меню ⋮ интеграции: отчёт должен открываться, а логин и пароль в нём — быть заменены на `***`.

## Обновление

### Через HACS

1. HACS → ReglerPro Controller → **Обновить**.
2. **Перезапустите Home Assistant.**

### Вручную

1. Замените содержимое `custom_components/kotel/` файлами новой версии (список — в разделе [Ручная установка](#ручная-установка)).
2. **Перезапустите Home Assistant.**

Перед обновлением рекомендуется создать резервную копию Home Assistant.

### С версии 1.4.0 до 1.4.1

1. Обновите файлы и **перезапустите Home Assistant**.
2. Это релиз упаковки: `hacs.json` переведён на `zip_release`, добавлен
   workflow сборки `kotel.zip`. Код интеграции, сущности и переводы не
   менялись.
3. При установке через HACS убедитесь, что в релизе есть asset `kotel.zip`.
   Если его нет, запустите workflow **Release zip** вручную для нужного тега:
   Actions → Release zip → Run workflow → указать тег.
4. Пользователям ручной установки zip не нужен: достаточно заменить
   `custom_components/kotel/`.

### С версии 1.3.1 до 1.4.0

1. Обновите файлы и **перезапустите Home Assistant**.
2. `unique_id` сущностей не меняются: автоматизации и дашборды продолжают
   работать. Отображаемые имена получают префикс имени устройства
   («Kotel контроллер · Температура воды»), унифицированы «макс.»/«мин.» и
   «Шнек: интервал (поддержание)»; `entity_id` в реестре остаётся прежним.
3. Все сущности и службы получили переводы. В русском интерфейсе названия
   остались прежними (кроме унификации «Шнек: интервал (поддержание)» и
   «Уставка температуры (макс./мин.)»); в английском появился перевод.
4. `scan_interval` из «Настроить → Опрос и параметры» теперь применяется;
   изменение интервала перезагружает интеграцию.
5. Появилась служба `kotel.send_command` и скачиваемая диагностика.
6. Состояния `да` / `нет`, `Остановлен`, `Нагрев` и названия пресетов
   **не менялись** — условия автоматизаций остаются рабочими.
7. Добавьте новый дашборд из `dashboards/` (Sections, Mushroom или Tablet)
   или оставьте прежний; в старом обновлены только комментарии и ID-примеры.

### С версии 1.3.0 до 1.3.1

1. Обновите файлы и **перезапустите Home Assistant**.
2. При первом запуске сохранённые профили **переносятся автоматически**: профили котла остаются профилями котла, профили с климатом, расписанием или датчиком становятся профилями климата, а смешанный профиль делится на два с одним именем. Перенос выполняется один раз.
3. Появятся 7 новых сущностей климата (список, имя, четыре кнопки, сенсор). У существующих сущностей котла идентификаторы не меняются, меняются только названия («Профиль» → «Профиль котла» и т. д.).
4. Автоматизации со службами профилей без параметра `kind` продолжают работать для профилей котла. Для профилей климата добавьте `kind: climate`.
5. В дашборд добавьте карточку «Профили климата» из `kotel_dashboard.yaml` (замените идентификаторы на свои).

Файлы экспорта версии 1 (из 1.3.0) импортируются; файлы версии 2 в 1.3.0 не читаются.

### С версии 1.2.x до 1.3.0

Новые сущности профилей появятся автоматически. Существующие сущности, автоматизации и дашборды не затрагиваются. Если у вас есть собственные `translations/`, объедините их с поставляемыми.

### С версии 1.1.x

Кроме шагов выше:

- **Удалены 8 сенсоров**, по которым прошивка не отдаёт данных: вентилятор (max/min), температура насоса, время продувки, интервал продувки, время угасания, коррекция температуры, заслонка вентилятора. Устаревшие записи удаляются из реестра при первом запуске. Замените ссылки на эти `sensor.*` в автоматизациях и дашбордах на соответствующие `number.*`.
- **Бинарные сенсоры** показывают «нет» / «да» вместо `0` / `1`. Условия вида `state: "1"` замените на `state: "да"`, а `state_not: "0"` на `state: "да"`.
- Появились климат-контроль (термостат, выбор датчика, расписание) и диагностические сенсоры.

Подробный список изменений: [RELEASE_NOTES.md](../RELEASE_NOTES.md).

## Дополнительно: дашборд и кнопка «F»

Пример дашборда использует только штатные карточки Home Assistant: панель контроллера с дисплеем и индикаторами, термостат, график, управление, профили и диагностика. Другие варианты (Sections, Mushroom, планшет) и их сравнение — в [dashboards/README.md](../dashboards/README.md).

1. Скопируйте `www/kotel/controller.png` в `/config/www/kotel/controller.png` (если папки `www` не было, после её создания перезапустите Home Assistant).
2. Для кнопки «F», которая листает показания на дисплее, положите `packages/kotel_display.yaml` в `/config/packages/` и добавьте в `configuration.yaml`:

   ```yaml
   homeassistant:
     packages: !include_dir_named packages
   ```

3. Перезапустите Home Assistant.
4. Создайте панель: **Настройки → Панели → Добавить панель → Новая панель с нуля**, затем в режиме правки откройте «Raw configuration editor» и вставьте содержимое `kotel_dashboard.yaml`.
5. **Замените ID сущностей на свои.** Реальные ID зависят от названия вашего устройства; посмотреть их можно в карточке устройства.

## Файлы и каталоги, которые создаёт интеграция

| Путь | Назначение | Когда появляется |
|---|---|---|
| `/config/.storage/kotel.profiles` | сохранённые профили | при первом сохранении профиля |
| `/config/kotel_profiles/` | файлы экспорта и импорта профилей | при первом экспорте (файл для импорта кладёте вы) |
| `/config/www/kotel_profiles/` | экспорт «для скачивания» (ссылка `/local/kotel_profiles/...` доступна **без авторизации**) | только если отмечен соответствующий флажок |

## Отладка

Самый быстрый способ собрать информацию — **Настройки → Устройства и службы →
ReglerPro Controller → ⋮ → Скачать диагностику**. В отчёте нет логина и
пароля, но есть состояние координатора и разобранные параметры.

Для подробных логов добавьте в `configuration.yaml`:

```yaml
logger:
  default: warning
  logs:
    custom_components.kotel: debug
```

В логе появятся названия запросов и ответы сервера. Перед публикацией логов проверьте их на наличие данных учётной записи.

Полезные атрибуты сенсора **«Диагностика параметров»**: `params_format` (`json` или `markers`), `params` (разобранные значения), `params_raw` (исходная строка), `climate`, `tstatArr`, `raw_keys`.

## Удаление

1. **Настройки → Устройства и службы → ReglerPro Controller → ⋮ → Удалить.**
2. При необходимости удалите папку `custom_components/kotel/` и перезапустите Home Assistant.
3. Файл профилей `/config/.storage/kotel.profiles` при удалении интеграции **остаётся**: так профили не теряются при переустановке. Чтобы удалить их окончательно, удалите файл вручную; файлы экспорта в `/config/kotel_profiles/` тоже удаляются вручную.

## Решение проблем

| Проблема | Причина и решение |
|---|---|
| Интеграции нет в списке «Добавить интеграцию» | папка скопирована не в `custom_components/kotel/` (проверьте вложенность) или не выполнен перезапуск |
| «Не удалось подключиться к серверу» | проверьте адрес сервера, логин и пароль, доступ Home Assistant в интернет; включите [отладку](#отладка) |
| «Устройства не найдены. Укажите ID дома» | сервер не вернул устройства по логину и паролю; введите ID дома |
| Сенсоры «неизвестно» | контроллер не в сети или параметр не поддерживается прошивкой; смотрите «Диагностику параметров» |
| Нет иконки интеграции | требуется Home Assistant 2026.3.0 и новее и папка `brand/`; после обновления сделайте жёсткое обновление страницы (Ctrl+Shift+R) |
| Экспорт или удаление профилей сообщают «Сохранённых профилей нет» | профили ещё не сохранены |
| «Контроллер не в сети: применение невозможно» | статус подключения `offline`; подождите, пока контроллер появится в сети, или используйте параметр `force: true` |
| «Файл не найден» при импорте | файл должен лежать в `/config/kotel_profiles/` и иметь расширение `.json` |
| На карточке дашборда жёлтый знак | сущности с указанным ID нет: проверьте ID в карточке устройства |
| Кнопки профилей недоступны | «Отменить применение» доступна только после применения; остальные не работают при ошибке связи с сервером |
| После обновления не появились новые сущности | не выполнен перезапуск Home Assistant |
| «Профиль … есть и у котла, и у климата: укажите kind» | одно имя есть в двух списках; добавьте в службу `kind: boiler` или `kind: climate` |
| «Профиль сохранён для режима …, а сейчас включён …» | «Обновить профиль климата» в другом режиме расписания; верните режим или сохраните новый профиль |
| После применения профиля климата климат не работает | профиль не включает климат-контроль; включите термостат (`climate.turn_on`) |
| Часть значений профиля «не подтверждена» | контроллер отвечает с задержкой; повторите применение или проверьте значения вручную |
| «Устройство уже настроено» | эта связка «сервер + логин + ID дома» уже добавлена; удалите дубль или измените ID дома |
| После смены пароля данные не обновляются | reauth-flow пока нет: удалите запись интеграции и добавьте её заново с новым паролем |
