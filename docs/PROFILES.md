# Профили настроек

Профиль — именованный набор значений, который можно сохранить и позже применить одной кнопкой, автоматизацией или службой. Начиная с версии **1.3.1** профили бывают двух типов, которые хранятся, выбираются, применяются и откатываются **независимо друг от друга**:

| Тип | В интерфейсе | Что внутри | Примеры |
|---|---|---|---|
| **Профиль котла** (`boiler`) | «Профиль котла» | 11 настроек котла: уставки max/min, температура насоса, коррекция, продувка, вентилятор min/max, время угасания, интервалы шнека | «Зима», «Лето», «Отпуск» |
| **Профиль климата** (`climate`) | «Профиль климата» | режим климат-контроля, целевая температура и расписание; по желанию выбранный датчик | «Расписание 7/7 — солнечные дни», «Расписание 7/7 — пасмурные дни» |

Профили хранятся **отдельно для каждого контроллера**; до 20 профилей каждого типа. Имена котла и климата не пересекаются: профиль «Зима» может быть и у котла, и у климата.

Например, вы выбираете профиль котла «Отпуск», а профиль климата переключаете между «Расписание 7/7 — солнечные дни» и «Расписание 7/7 — пасмурные дни», не затрагивая настройки котла.

## Что сохраняется

| Область (`scopes`) | Что входит | Тип профиля | По умолчанию |
|---|---|---|---|
| `boiler` | 11 настроек котла | котёл | да |
| `climate` | режим климат-контроля (`0`, `3`, `4`, `5`) и целевая температура | климат | да |
| `schedule` | расписание климат-контроля (до 48 значений) | климат | да |
| `climate_sensor` | выбранный датчик климат-контроля | климат | нет (датчик привязан к дому) |

Старт/стоп и включение/выключение климат-контроля в профили **не входят**: это сознательное ограничение безопасности. Применение профиля климата меняет режим, температуру и расписание, но не включает и не выключает климат.

### Расписание в профиле климата

В профиль попадает расписание **только активного режима**:

| Режим на момент сохранения | Что сохраняется |
|---|---|
| расписание 7/7 | режим, цель и ключи `m3_*` |
| расписание 5/2 | режим, цель и ключи `m4_*` |
| расписание 4/1/2 | режим, цель и ключи `m5_*` |
| постоянная температура | режим и цель; расписание не сохраняется |

Так профиль «7/7 — солнечные дни» не затрагивает наборы 5/2 и 4/1/2. Чтобы сохранить все наборы сразу, используйте `all_schedules: true`.

Профиль климата запоминает режим, для которого он сохранён. Если режим изменился, кнопка и служба **«Обновить профиль»** откажут: иначе в профиль 7/7 попали бы значения 5/2. Сохраните новый профиль или верните режим.

## Быстрый старт

В карточке устройства (или на дашборде) для каждого типа профилей есть свой набор сущностей.

**Профиль котла:**

1. Настройте котёл.
2. Введите имя в поле **«Имя нового профиля котла»**, нажмите **«Сохранить профиль котла»**.
3. Позже выберите профиль в списке **«Профиль котла»** и нажмите **«Применить профиль котла»**.
4. Результат не устроил? **«Отменить применение (котёл)»** вернёт прежние значения.

**Профиль климата:**

1. Выберите режим расписания и настройте температуры периодов.
2. Введите имя в поле **«Имя нового профиля климата»**, нажмите **«Сохранить профиль климата»**.
3. Выберите профиль в списке **«Профиль климата»** и нажмите **«Применить профиль климата»**.
4. **«Отменить применение (климат)»** вернёт прежнее расписание.

Выбор в списке только выбирает профиль, применяется он кнопкой: это защищает от случайной перезаписи десятков параметров. Кнопки «Обновить профиль …» перезаписывают выбранный профиль текущими значениями.

## Сущности

Для каждого контроллера создаётся по две копии сущностей: для котла и для климата.

| Сущность | Профиль котла | Профиль климата |
|---|---|---|
| `select` | «Профиль котла» | «Профиль климата» |
| `text` | «Имя нового профиля котла» | «Имя нового профиля климата» |
| `button` сохранить | «Сохранить профиль котла» | «Сохранить профиль климата» |
| `button` обновить | «Обновить профиль котла» | «Обновить профиль климата» |
| `button` применить | «Применить профиль котла» | «Применить профиль климата» |
| `button` отменить | «Отменить применение (котёл)» | «Отменить применение (климат)» |
| `sensor` активный профиль | «Активный профиль котла» | «Активный профиль климата» |

Кнопки отката доступны только после применения профиля соответствующего типа.

Сенсор «Активный профиль …» показывает имя профиля, чьи значения совпадают с текущими, либо `изменён` или `нет профилей`. Атрибуты: `kind`, `profiles`, `selected`, `last_applied`, `last_applied_at`, `last_applied_ok`, `has_undo`.

> У пользователей версии 1.3.0 сущности котла сохраняют прежние идентификаторы (например, `select.kotel_kontroller_profil`); меняются только отображаемые названия. Сущности климата получают новые идентификаторы (например, `select.kotel_kontroller_profil_klimata`).

## Службы

Все службы принимают необязательную цель `device_id`. Если контроллер один, цель можно не указывать.

| Служба | Назначение | Ответ |
|---|---|---|
| `kotel.save_profile` | сохранить профиль | да |
| `kotel.apply_profile` | применить профиль | да |
| `kotel.undo_apply` | отменить последнее применение | да |
| `kotel.rename_profile` | переименовать | нет |
| `kotel.delete_profile` | удалить | нет |
| `kotel.list_profiles` | список профилей | да (только ответ) |
| `kotel.export_profiles` | экспорт в файл | да |
| `kotel.import_profiles` | импорт из файла | да |

### Параметр `kind` (тип профиля)

| Служба | Как определяется тип, если `kind` не указан |
|---|---|
| `save_profile` | по областям `scopes`; если область не указана — котёл. Смешанные области (`boiler` вместе с `climate`/`schedule`) отклоняются |
| `apply_profile`, `delete_profile`, `rename_profile` | по имени: если профиль с таким именем есть только в одном списке — берётся он; если в обоих, нужно указать `kind` |
| `undo_apply` | котёл |
| `export_profiles`, `import_profiles` | оба типа |

Поэтому существующие автоматизации версии 1.3.0 (`apply_profile` с одним лишь именем котельного профиля) продолжают работать без изменений.

### Параметры

| Служба | Параметры |
|---|---|
| `save_profile` | `name` (обязательно), `kind`, `scopes` (по умолчанию `boiler` для котла и `climate` + `schedule` для климата), `note`, `overwrite` (`false`), `all_schedules` (`false`) |
| `apply_profile` | `name` (обязательно), `kind`, `scopes` (по умолчанию все области профиля), `dry_run`, `force`, `verify` (`true`) |
| `undo_apply` | `kind` (`boiler`), `force`, `verify` |
| `rename_profile` | `name`, `new_name`, `kind` |
| `delete_profile` | `name`, `kind` |
| `export_profiles` | `profiles` (имена; по умолчанию все), `kind`, `to_www` |
| `import_profiles` | `file` (обязательно), `profiles`, `kind`, `on_conflict`: `rename` (по умолчанию), `overwrite`, `skip` |

### Примеры

```yaml
# Сохранить профиль котла
action: kotel.save_profile
data:
  name: Отпуск
```

```yaml
# Сохранить профиль климата (режим и расписание активного режима)
action: kotel.save_profile
data:
  name: Расписание 7/7 — солнечные дни
  kind: climate
  note: Яркая погода, меньше нагрев
```

```yaml
# Посмотреть, что изменится, ничего не записывая
action: kotel.apply_profile
data:
  name: Расписание 7/7 — пасмурные дни
  dry_run: true
response_variable: plan
```

```yaml
# Откатить только климат
action: kotel.undo_apply
data:
  kind: climate
```

### Ответ `list_profiles`

```yaml
devices:
  "6008555528819":
    name: Дом
    # профили котла — на верхнем уровне (как в версии 1.3.0)
    selected: Отпуск
    matching: Отпуск
    has_undo: true
    last_applied: {name: Отпуск, at: "2026-10-22T09:00:00+00:00", ok: true}
    profiles: [{name: Отпуск, kind: boiler, scopes: [boiler], values: 11}]
    # то же для котла и отдельно для климата
    boiler: {selected: Отпуск, profiles: [...]}
    climate:
      selected: Расписание 7/7 — солнечные дни
      matching: Расписание 7/7 — солнечные дни
      profiles: [{name: Расписание 7/7 — солнечные дни, kind: climate, mode: 3, scopes: [climate, schedule], values: 10}]
```

Ответ `apply_profile` и `undo_apply` содержит: `kind`, `changes` (что меняется: `scope`, `key`, `from`, `to`), `unchanged`, `skipped` (с причиной), `applied`, `failed`, `unverified` и итоговый флаг `ok`.

## Как применяется профиль

1. **Проверка связи.** Если контроллер не в сети, применение отклоняется (`force: true` отключает проверку).
2. **Разница.** Записываются только параметры, которые отличаются от текущих значений.
3. **Проверка значений.** Значения вне допустимых диапазонов не записываются и попадают в `skipped` с причиной.
4. **Порядок записи.** Сначала датчик климата, затем режим и целевая температура, затем расписание, затем настройки котла. Время периодов расписания должно строго возрастать (P1 < P2 < P3 < P4), поэтому оно записывается в безопасном порядке; профиль, нарушающий порядок, отклоняется.
5. **Независимость.** Профиль котла пишет только настройки котла, профиль климата — только климат. У каждого типа свои «выбранный», «последний применённый» и «откат».
6. **Откат.** Перед записью сохраняются прежние значения изменяемых параметров соответствующего типа.
7. **Проверка результата.** После записи интеграция ждёт, пока контроллер вернёт новые значения (до 20 секунд).
8. **Очередь.** Команды одного контроллера выполняются строго по очереди, даже если профили котла и климата запущены одновременно.

## Примеры переключения

Профили из примеров должны быть уже сохранены. Тип профиля определяется по имени; если одно и то же имя есть у котла и у климата, добавьте `kind`.

### 1. Вручную

**Кнопки на дашборде.** Пример дашборда `kotel_dashboard.yaml` содержит карточки «Профили котла» и «Профили климата».

**Одна кнопка — один профиль:**

```yaml
type: button
name: "Погода: пасмурно"
icon: mdi:weather-cloudy
tap_action:
  action: perform-action
  perform_action: kotel.apply_profile
  data:
    name: Расписание 7/7 — пасмурные дни
    kind: climate
```

**Скрипт «Отпуск» (котёл и климат сразу):**

```yaml
script:
  kotel_vacation:
    alias: Котёл — режим «Отпуск»
    sequence:
      - action: kotel.apply_profile
        data:
          name: Отпуск
          kind: boiler
        response_variable: boiler_result
      - action: kotel.apply_profile
        data:
          name: Отпуск
          kind: climate
        response_variable: climate_result
      - if:
          - condition: template
            value_template: "{{ not (boiler_result.ok and climate_result.ok) }}"
        then:
          - action: persistent_notification.create
            data:
              title: Котёл
              message: >-
                Режим «Отпуск» применён не полностью:
                котёл — ошибок {{ boiler_result.failed | length }},
                климат — ошибок {{ climate_result.failed | length }}.
```

### 2. По расписанию

**Профиль котла по сезону, профиль климата по времени суток:**

```yaml
automation:
  - alias: Котёл — профиль по сезону
    triggers:
      - trigger: state
        entity_id: sensor.season
    actions:
      - action: kotel.apply_profile
        data:
          kind: boiler
          name: >-
            {{ {'winter': 'Зима', 'spring': 'Весна',
                'summer': 'Лето', 'autumn': 'Осень'}[trigger.to_state.state] }}

  - alias: Климат — ночное расписание
    triggers:
      - trigger: time
        at: "22:30:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: Расписание 7/7 — ночь
          kind: climate

  - alias: Климат — дневное расписание
    triggers:
      - trigger: time
        at: "06:00:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: Расписание 7/7 — день
          kind: climate
```

**Выходные и будни:**

```yaml
automation:
  - alias: Климат — выходной день
    triggers:
      - trigger: time
        at: "07:00:00"
    actions:
      - action: kotel.apply_profile
        data:
          kind: climate
          name: "{{ 'Расписание 5/2 — выходной' if now().weekday() >= 5 else 'Расписание 5/2 — будни' }}"
```

**Применять только когда контроллер в сети:**

```yaml
automation:
  - alias: Котёл — профиль «День» с проверкой связи
    triggers:
      - trigger: time
        at: "06:00:00"
    conditions:
      - condition: state
        entity_id: sensor.kotel_kontroller_status_podkliucheniia   # замените на свой ID
        state: online
    actions:
      - action: kotel.apply_profile
        data:
          name: День
          kind: boiler
```

### 3. По событиям

**Погода: солнечные и пасмурные дни** (профиль климата по состоянию `weather`):

```yaml
automation:
  - alias: Климат — расписание по погоде
    triggers:
      - trigger: state
        entity_id: weather.home          # замените на свою сущность погоды
        for: "01:00:00"
    actions:
      - choose:
          - conditions:
              - condition: template
                value_template: "{{ trigger.to_state.state in ['sunny', 'clear-night'] }}"
            sequence:
              - action: kotel.apply_profile
                data:
                  name: Расписание 7/7 — солнечные дни
                  kind: climate
          - conditions:
              - condition: template
                value_template: "{{ trigger.to_state.state in ['cloudy', 'rainy', 'fog', 'snowy', 'pouring'] }}"
            sequence:
              - action: kotel.apply_profile
                data:
                  name: Расписание 7/7 — пасмурные дни
                  kind: climate
```

**Присутствие: отъезд и возвращение** (`zone.home` показывает число людей дома):

```yaml
automation:
  - alias: Котёл — отъезд
    triggers:
      - trigger: state
        entity_id: zone.home
        to: "0"
        for: "02:00:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: Отпуск
          kind: boiler

  - alias: Котёл — возвращение
    triggers:
      - trigger: numeric_state
        entity_id: zone.home
        above: 0
    actions:
      - action: kotel.apply_profile
        data:
          name: Дома
          kind: boiler
```

**Уличная температура** (профиль котла, с гистерезисом):

```yaml
automation:
  - alias: Котёл — профиль «Мороз»
    triggers:
      - trigger: numeric_state
        entity_id: sensor.outdoor_temperature   # замените на свой датчик
        below: -15
        for: "00:30:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: Мороз
          kind: boiler

  - alias: Котёл — выход из режима «Мороз»
    triggers:
      - trigger: numeric_state
        entity_id: sensor.outdoor_temperature
        above: -8
        for: "02:00:00"
    conditions:
      - condition: state
        entity_id: sensor.kotel_kontroller_aktivnyi_profil   # замените на свой ID
        state: Мороз
    actions:
      - action: kotel.apply_profile
        data:
          name: Зима
          kind: boiler
```

**Событие календаря** (отпуск включает профили котла и климата):

```yaml
automation:
  - alias: Котёл — отпуск начинается
    triggers:
      - trigger: calendar
        event: start
        entity_id: calendar.family
    conditions:
      - condition: template
        value_template: "{{ 'Отпуск' in trigger.calendar_event.summary }}"
    actions:
      - action: script.kotel_vacation
```

**Выбор режима дома** (помощник `input_select`, названия вариантов совпадают с именами профилей климата):

```yaml
automation:
  - alias: Климат — профиль по режиму дома
    triggers:
      - trigger: state
        entity_id: input_select.kotel_house_mode
    actions:
      - action: kotel.apply_profile
        data:
          kind: climate
          name: "{{ trigger.to_state.state }}"
```

**Уведомление о результате** (по событию `kotel_profile_applied`):

```yaml
automation:
  - alias: Котёл — отчёт о применении профиля
    triggers:
      - trigger: event
        event_type: kotel_profile_applied
    actions:
      - action: notify.notify
        data:
          title: Котёл
          message: >-
            {{ 'Климат' if trigger.event.data.kind == 'climate' else 'Котёл' }}:
            {% if trigger.event.data.undo %}откат{% else %}профиль «{{ trigger.event.data.profile }}»{% endif %},
            применено {{ trigger.event.data.applied }},
            {{ 'без ошибок' if trigger.event.data.ok else 'есть ошибки или неподтверждённые значения' }}.
```

## Экспорт и импорт

### Через интерфейс

**Настройки → Устройства и службы → Kotel → Настроить:**

| Пункт | Что делает |
|---|---|
| Экспорт профилей в файл | флажками выбираются профили; в списке они подписаны «Котёл · имя» и «Климат · имя» |
| Импорт профилей из файла | выбирается файл, затем профили, контроллер и поведение при совпадении имён |
| Удалить профили | флажками выбираются профили (необратимо) |
| Опрос и параметры | интервал опроса |

### Перенос между установками

1. На первой установке выберите **Экспорт** и отметьте нужные профили (можно выбрать только профили климата или только котла).
2. Скопируйте файл из `/config/kotel_profiles/` (File editor, Samba, SSH). Вариант **«положить в www»** делает файл доступным по ссылке `/local/kotel_profiles/...`: **ссылка работает без авторизации**, поэтому после скачивания файл лучше удалить.
3. На второй установке положите файл в `/config/kotel_profiles/`.
4. Выберите **Импорт**, файл, профили и контроллер.

При совпадении имён: **добавить с номером** `(2)` (по умолчанию), **заменить** или **пропустить**. Имена сравниваются внутри своего типа: импорт профиля климата «Зима» не затрагивает профиль котла «Зима».

Если два экспорта выполнены в одну секунду, второй файл получает суффикс `_2`: файлы не перезаписываются.

### Через службы

```yaml
# Экспортировать только профили климата
action: kotel.export_profiles
data:
  kind: climate
response_variable: exported     # exported.path, filename, count, boiler, climate
```

```yaml
# Импортировать только один профиль климата, заменяя существующий
action: kotel.import_profiles
data:
  file: kotel_profiles_20261022_101500.json
  profiles: [Расписание 7/7 — солнечные дни]
  kind: climate
  on_conflict: overwrite
response_variable: imported     # imported.imported, imported.skipped, imported.renamed
```

### Формат файла (версия 2)

```json
{
  "format": "kotel-profiles",
  "version": 2,
  "exported": "2026-10-22T10:15:00",
  "profiles": [
    {
      "kind": "boiler",
      "name": "Отпуск",
      "scopes": ["boiler"],
      "values": {"boiler": {"temp_w_ust": 30, "vent_max": 40}}
    },
    {
      "kind": "climate",
      "name": "Расписание 7/7 — солнечные дни",
      "mode": 3,
      "scopes": ["climate", "schedule"],
      "values": {
        "climate": {"tstat_mode": 3, "tstatTemp": 24},
        "schedule": {"m3_P1_time": 0, "m3_P1_temp": 25}
      }
    }
  ]
}
```

В файле нет логина, пароля и адресов серверов. При импорте файл проверяется: принимаются только известные области и параметры, значения должны быть числами, имена очищаются, размер ограничен 1 МБ, имя файла не может выходить за каталог `kotel_profiles`.

**Совместимость.** Файлы версии 1 (из Kotel 1.3.0) импортируются как есть: профиль со смешанным содержимым автоматически делится на профиль котла и профиль климата с тем же именем. Файлы версии 2 в Kotel 1.3.0 не читаются.

## Обновление с версии 1.3.0

При первом запуске версии 1.3.1 сохранённые профили переносятся в новую схему автоматически (в файле хранилища появляется поле `schema: 2`):

- профили, содержавшие только настройки котла, остаются профилями котла;
- профили, содержавшие только климат, расписание или датчик, становятся профилями климата;
- **смешанный профиль делится на два** с одним именем: в список котла попадает часть `boiler`, в список климата — остальное;
- выбранный профиль, последнее применение и состояние отката разносятся по типам;
- существующие сущности котла сохраняют идентификаторы; добавляются сущности климата.

Миграция выполняется один раз и не повторяется. Перед обновлением рекомендуется резервная копия.

## События

| Событие | Когда | Данные |
|---|---|---|
| `kotel_profile_saved` | профиль сохранён | `device_id`, `kind`, `profile`, `scopes`, `overwritten` |
| `kotel_profile_applied` | применение или откат завершены | `device_id`, `kind`, `profile` (`null` при откате), `undo`, `ok`, `applied`, `failed`, `unverified` |

## Ограничения

- До **20 профилей каждого типа** на контроллер, имя до **40 символов**.
- Параметр записывается только если контроллер его отдаёт: набор параметров зависит от прошивки.
- Значения настроек котла приходят от устройства с задержкой; проверка результата ждёт до 20 секунд.
- Ключи расписания 5/2 и 4/1/2 появляются на сервере после первой записи; если профиль содержит их, а сервер ещё не создал, они записываются «с нуля».
- Профиль климата не включает и не выключает климат-контроль: если он выключен, режим и расписание записываются, но не действуют до включения.
- Профили общие для одной установки Home Assistant; при удалении интеграции из интерфейса файл профилей остаётся в `.storage/`.
- Одновременное изменение параметров в веб-приложении во время применения профиля может привести к расхождению; результат проверки покажет это.
