# Профили настроек

Профиль — именованный набор настроек одного контроллера (например, «Зима», «Лето», «Отпуск»). Профили можно сохранять сколько угодно раз (до 20 на контроллер), переключаться между ними вручную, по расписанию или по событиям, а также переносить в файл между установками Home Assistant.

## Что сохраняется

Профили хранятся **отдельно для каждого контроллера**. Состав выбирается областями (`scopes`):

| Область | Что входит | По умолчанию |
|---|---|---|
| `boiler` | 11 настроек котла: уставки max/min, температура насоса, коррекция, время и интервал продувки, вентилятор min/max, время угасания, интервалы шнека | **да** |
| `climate` | режим климат-контроля и целевая температура | нет |
| `schedule` | расписание климат-контроля (до 48 значений) | нет |
| `climate_sensor` | выбранный датчик климат-контроля | нет |

В профили **не входят** старт/стоп и включение/выключение климат-контроля: это сознательное ограничение безопасности.

Профили лежат в файле `.storage/kotel.profiles` и попадают в резервные копии Home Assistant.

## Быстрый старт

В карточке устройства (или на дашборде) есть пять сущностей:

1. Настройте котёл, как нужно.
2. Введите имя в поле **«Имя нового профиля»** и нажмите **«Сохранить профиль»**.
3. Позже выберите профиль в списке **«Профиль»** и нажмите **«Применить профиль»**.
4. Если результат не устроил, нажмите **«Отменить применение»**: вернутся значения, которые были до применения.
5. Чтобы обновить профиль текущими значениями, выберите его и нажмите **«Обновить профиль»**.

Выбор в списке только выбирает профиль, он применяется кнопкой. Это защищает от случайной перезаписи десятков параметров.

## Сущности

| Сущность | Назначение |
|---|---|
| `select` «Профиль» | выбор сохранённого профиля |
| `text` «Имя нового профиля» | имя для кнопки «Сохранить профиль» |
| `button` «Сохранить профиль» | сохранить текущие настройки котла под введённым именем |
| `button` «Обновить профиль» | перезаписать выбранный профиль текущими значениями (с теми же областями) |
| `button` «Применить профиль» | записать выбранный профиль в контроллер |
| `button` «Отменить применение» | вернуть значения до последнего применения (доступна только после применения) |
| `sensor` «Активный профиль» | имя профиля, совпадающего с текущими настройками; `изменён`, если ни один не совпадает; `нет профилей` |

Атрибуты сенсора «Активный профиль»: `profiles`, `selected`, `last_applied`, `last_applied_at`, `last_applied_ok`, `has_undo`.

## Службы

Все службы принимают необязательную цель `device_id`. Если контроллер один, цель можно не указывать.

| Служба | Назначение | Ответ |
|---|---|---|
| `kotel.save_profile` | сохранить профиль | да |
| `kotel.apply_profile` | применить профиль | да |
| `kotel.undo_apply` | отменить последнее применение | да |
| `kotel.rename_profile` | переименовать | нет |
| `kotel.delete_profile` | удалить | нет |
| `kotel.list_profiles` | список профилей | да (только ответ) |
| `kotel.export_profiles` | экспорт в файл | да |
| `kotel.import_profiles` | импорт из файла | да |

Параметры:

| Служба | Параметры |
|---|---|
| `save_profile` | `name` (обязательно), `scopes` (по умолчанию `[boiler]`), `note`, `overwrite` (по умолчанию `false`) |
| `apply_profile` | `name` (обязательно), `scopes` (по умолчанию все области профиля), `dry_run`, `force`, `verify` (по умолчанию `true`) |
| `undo_apply` | `force`, `verify` |
| `export_profiles` | `profiles` (список имён; по умолчанию все), `to_www` |
| `import_profiles` | `file` (обязательно), `profiles`, `on_conflict`: `rename` (по умолчанию), `overwrite`, `skip` |

Примеры:

```yaml
# Сохранить текущие настройки котла и расписание климата
action: kotel.save_profile
data:
  name: Зима
  scopes: [boiler, climate, schedule]
  note: Для морозов ниже -15 °C
```

```yaml
# Посмотреть, что изменится, ничего не записывая
action: kotel.apply_profile
data:
  name: Зима
  dry_run: true
response_variable: plan
```

Ответ `apply_profile` содержит: `changes` (что меняется: `scope`, `key`, `from`, `to`), `unchanged`, `skipped` (с причиной), `applied`, `failed`, `unverified` и итоговый флаг `ok`.

## Как применяется профиль

1. **Проверка связи.** Если контроллер не в сети, применение отклоняется (параметр `force: true` отключает проверку).
2. **Разница.** Записываются только параметры, которые отличаются от текущих значений, поэтому лишних запросов к облаку нет.
3. **Проверка значений.** Значения вне допустимого диапазона (например, из файла, созданного для другой прошивки) не записываются и попадают в `skipped` с причиной.
4. **Порядок записи.** Сначала датчик климата, затем режим и целевая температура, затем расписание, затем настройки котла. Время периодов расписания должно строго возрастать (P1 < P2 < P3 < P4), поэтому оно записывается в безопасном порядке: сначала понижения по возрастанию периодов, затем повышения по убыванию. Профиль, нарушающий порядок, отклоняется.
5. **Откат.** Перед записью сохраняются прежние значения изменяемых параметров; их можно вернуть кнопкой «Отменить применение» или службой `undo_apply`.
6. **Проверка результата.** После записи интеграция ждёт, пока контроллер вернёт новые значения (до 20 секунд), и сообщает о неподтверждённых.
7. **Блокировка.** Команды одного контроллера выполняются строго по очереди.

## Примеры переключения

Во всех примерах профили «Зима», «Лето», «Ночь», «День» и т. д. должны быть уже сохранены. Для надёжности можно проверять результат: служба возвращает `ok`.

### 1. Вручную

**С дашборда.** Карточка из файла `kotel_dashboard.yaml` содержит выбор профиля и кнопки.

**Кнопка быстрого переключения** (одна кнопка — один профиль):

```yaml
type: button
name: Режим «Зима»
icon: mdi:snowflake
tap_action:
  action: perform-action
  perform_action: kotel.apply_profile
  data:
    name: Зима
```

**Скрипт с уведомлением об ошибке:**

```yaml
script:
  kotel_apply_winter:
    alias: Котёл — режим «Зима»
    sequence:
      - action: kotel.apply_profile
        data:
          name: Зима
        response_variable: result
      - if:
          - condition: template
            value_template: "{{ not result.ok }}"
        then:
          - action: persistent_notification.create
            data:
              title: Котёл
              message: >-
                Профиль «Зима» применён не полностью:
                ошибок {{ result.failed | length }},
                не подтверждено {{ result.unverified | length }}.
```

### 2. По расписанию

**Ночной и дневной режимы по времени:**

```yaml
automation:
  - alias: Котёл — ночной профиль
    triggers:
      - trigger: time
        at: "22:30:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: Ночь

  - alias: Котёл — дневной профиль
    triggers:
      - trigger: time
        at: "06:00:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: День
```

**По дням недели** (в выходные другой профиль):

```yaml
automation:
  - alias: Котёл — профиль выходного дня
    triggers:
      - trigger: time
        at: "07:00:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: "{{ 'Выходной' if now().weekday() >= 5 else 'Будни' }}"
```

**По сезону** (встроенная интеграция Season, сенсор `sensor.season`):

```yaml
automation:
  - alias: Котёл — профиль по сезону
    triggers:
      - trigger: state
        entity_id: sensor.season
    actions:
      - action: kotel.apply_profile
        data:
          name: >-
            {{ {'winter': 'Зима', 'spring': 'Весна',
                'summer': 'Лето', 'autumn': 'Осень'}[trigger.to_state.state] }}
```

**Применять только когда контроллер в сети:**

```yaml
automation:
  - alias: Котёл — профиль «День» с проверкой связи
    triggers:
      - trigger: time
        at: "06:00:00"
    conditions:
      - condition: state
        entity_id: sensor.kotel_kontroller_status_podkliucheniia   # замените на свой ID
        state: online
    actions:
      - action: kotel.apply_profile
        data:
          name: День
```

### 3. По событиям

**Присутствие: отъезд и возвращение** (`zone.home` показывает число людей дома):

```yaml
automation:
  - alias: Котёл — отъезд
    triggers:
      - trigger: state
        entity_id: zone.home
        to: "0"
        for: "02:00:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: Отъезд

  - alias: Котёл — возвращение
    triggers:
      - trigger: numeric_state
        entity_id: zone.home
        above: 0
    actions:
      - action: kotel.apply_profile
        data:
          name: Дома
```

**Уличная температура** (с гистерезисом, чтобы не переключаться туда-сюда):

```yaml
automation:
  - alias: Котёл — профиль «Мороз»
    triggers:
      - trigger: numeric_state
        entity_id: sensor.outdoor_temperature   # замените на свой датчик
        below: -15
        for: "00:30:00"
    actions:
      - action: kotel.apply_profile
        data:
          name: Мороз

  - alias: Котёл — выход из режима «Мороз»
    triggers:
      - trigger: numeric_state
        entity_id: sensor.outdoor_temperature
        above: -8
        for: "02:00:00"
    conditions:
      - condition: state
        entity_id: sensor.kotel_kontroller_aktivnyi_profil   # замените на свой ID
        state: Мороз
    actions:
      - action: kotel.apply_profile
        data:
          name: Зима
```

**Событие календаря** (событие «Отпуск» включает профиль, окончание возвращает обычный):

```yaml
automation:
  - alias: Котёл — отпуск начинается
    triggers:
      - trigger: calendar
        event: start
        entity_id: calendar.family
    conditions:
      - condition: template
        value_template: "{{ 'Отпуск' in trigger.calendar_event.summary }}"
    actions:
      - action: kotel.apply_profile
        data:
          name: Отпуск

  - alias: Котёл — отпуск закончился
    triggers:
      - trigger: calendar
        event: end
        entity_id: calendar.family
    conditions:
      - condition: template
        value_template: "{{ 'Отпуск' in trigger.calendar_event.summary }}"
    actions:
      - action: kotel.apply_profile
        data:
          name: Дома
```

**Выбор режима дома** (помощник `input_select`, названия вариантов совпадают с именами профилей):

```yaml
automation:
  - alias: Котёл — профиль по режиму дома
    triggers:
      - trigger: state
        entity_id: input_select.kotel_house_mode
    actions:
      - action: kotel.apply_profile
        data:
          name: "{{ trigger.to_state.state }}"
```

**Уведомление о результате** (по событию `kotel_profile_applied`):

```yaml
automation:
  - alias: Котёл — отчёт о применении профиля
    triggers:
      - trigger: event
        event_type: kotel_profile_applied
    actions:
      - action: notify.notify
        data:
          title: Котёл
          message: >-
            {% if trigger.event.data.undo %}Откат{% else %}Профиль «{{ trigger.event.data.profile }}»{% endif %}:
            применено {{ trigger.event.data.applied }},
            {{ 'без ошибок' if trigger.event.data.ok else 'есть ошибки или неподтверждённые значения' }}.
```

## Экспорт и импорт

### Через интерфейс

**Настройки → Устройства и службы → Kotel → Настроить** открывает меню:

| Пункт | Что делает |
|---|---|
| Экспорт профилей в файл | флажками выбираются нужные профили; создаётся файл `kotel_profiles/kotel_profiles_ГГГГММДД_ЧЧММСС.json` в папке конфигурации |
| Импорт профилей из файла | выбирается файл из каталога `kotel_profiles`, затем профили, контроллер и поведение при совпадении имён |
| Удалить профили | флажками выбираются профили для удаления (необратимо) |
| Опрос и параметры | интервал опроса |

### Перенос между установками

1. На первой установке выберите **Экспорт** и отметьте нужные профили.
2. Скопируйте файл из `/config/kotel_profiles/` (через File editor, Samba, SSH или Studio Code Server). Вариант **«положить в www для скачивания»** делает файл доступным по ссылке `/local/kotel_profiles/...`: **ссылка работает без авторизации**, поэтому после скачивания файл лучше удалить.
3. На второй установке положите файл в `/config/kotel_profiles/`.
4. Выберите **Импорт**, файл, профили и контроллер.

При совпадении имён: **добавить с номером** `(2)` (по умолчанию), **заменить** существующий или **пропустить**.

### Через службы

```yaml
# Экспорт выбранных профилей
action: kotel.export_profiles
data:
  profiles: [Зима, Лето]
response_variable: exported     # exported.path, exported.filename, exported.count
```

```yaml
# Импорт: профили из файла, при совпадении имён заменить
action: kotel.import_profiles
data:
  file: kotel_profiles_20261020_153045.json
  profiles: [Зима]
  on_conflict: overwrite
response_variable: imported     # imported.imported, imported.skipped, imported.renamed
```

### Формат файла

```json
{
  "format": "kotel-profiles",
  "version": 1,
  "exported": "2026-10-20T15:30:45",
  "profiles": [
    {
      "name": "Зима",
      "note": "Для морозов ниже -15 °C",
      "firmware": 291023,
      "scopes": ["boiler"],
      "values": {
        "boiler": {"temp_w_ust": 60, "vent_max": 80, "korect_": -3}
      },
      "created": "2026-10-01T09:00:00+00:00",
      "updated": "2026-10-20T12:00:00+00:00",
      "source": {"device_id": "...", "device_name": "Дом"}
    }
  ]
}
```

В файле нет логина, пароля и адресов серверов. При импорте файл проверяется: принимаются только известные области и параметры, значения должны быть числами, имена очищаются, размер ограничен 1 МБ, имя файла не может выходить за каталог `kotel_profiles`.

Профили, созданные для другой прошивки или другого котла, импортируются как есть, но при применении значения вне допустимых диапазонов пропускаются и отображаются в отчёте.

## События

| Событие | Когда | Данные |
|---|---|---|
| `kotel_profile_saved` | профиль сохранён | `device_id`, `profile`, `scopes`, `overwritten` |
| `kotel_profile_applied` | применение или откат завершены | `device_id`, `profile` (`null` при откате), `undo`, `ok`, `applied`, `failed`, `unverified` |

---

## Ограничения

- До **20 профилей** на контроллер, имя до **40 символов**.
- Параметр записывается только если контроллер его отдаёт: набор параметров зависит от прошивки.
- Значения настроек котла приходят от устройства с задержкой; проверка результата ждёт до 20 секунд, после этого значения считаются неподтверждёнными.
- Ключи расписания 5/2 и 4/1/2 появляются на сервере после первой записи. Если профиль содержит их, а сервер их ещё не создал, они записываются «с нуля».
- Профили общие для одной установки Home Assistant; при удалении интеграции из интерфейса файл профилей остаётся в `.storage/`.
- Одновременное изменение параметров в веб-приложении во время применения профиля может привести к расхождению; результат проверки покажет это.
