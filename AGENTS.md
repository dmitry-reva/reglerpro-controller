# Инструкции для ИИ-агентов

## О проекте

ReglerPro Controller — пользовательская интеграция для Home Assistant, получающая данные контроллеров ReglerPro через облачный API.

- `custom_components/kotel/` — код интеграции, сущности, конфигурация, переводы и манифест.
- `dashboards/` — примеры YAML-панелей и пакет для дополнительной карточки; описание и установка — в `dashboards/README.md`.
- `tests/` — unit-тесты, не требующие запущенного Home Assistant.
- `scripts/` — проверки переводов и сборка HACS-архива.
- `docs/` — подробные инструкции по установке, сущностям, климату, профилям и переводам.
- `.github/workflows/` — CI и выпуск архива для GitHub Release.

Перед изменением поведения интеграции проверь относящиеся к нему материалы в `docs/` и README. Не добавляй зависимости без необходимости: unit-тесты и проверка переводов рассчитаны на стандартную библиотеку Python.

## Навыки проекта

В `.github/skills/` находятся специализированные инструкции `SKILL.md`. Перед профильной задачей найди и прочитай соответствующий навык, следуй его процедурам и проверкам; он дополняет эти общие правила, а не заменяет их. Если задача затрагивает несколько областей, используй все подходящие навыки.

- `.github/skills/home-assistant-integration/SKILL.md` — изменения или отладка интеграции в `custom_components/kotel/`, связанных тестов и документации. Сверяй поведение и совместимость с кодом, тестами, `docs/` и README; сохраняй идентификаторы сущностей, значения состояний, формат и независимость профилей. Для пользовательского текста согласованно обновляй переводы. Не скрывай ошибки за тихими значениями по умолчанию.
- `.github/skills/lovelace-dashboard/SKILL.md` — изменение, проверка или документирование YAML-панелей и пакетов в `dashboards/`. Сохраняй подтверждение потенциально опасных действий и удаления профилей; учитывай безопасность экспорта профилей и явно документируй необходимые пользовательские карточки и замену примеров entity ID. Проверяй изменённый YAML и содержимое diff.
- `.github/skills/release-i18n-checks/SKILL.md` — подготовка релиза, версии, release notes, переводы, HACS-архив и проверки проекта. Сверяй версию манифеста, README, заметок и тега; не выдумывай изменения релиза и не коммить результат сборки из `dist/`.

## Проверки

CI выполняет следующие проверки из корня репозитория:

```text
python -m compileall -q custom_components
python -m unittest discover -s tests -v
python scripts/check_i18n.py
```

Для YAML-дашбордов CI устанавливает `pyyaml` и проверяет YAML-файлы в `dashboards/` и `dashboards/packages/`. Сборку релизного архива выполняет:

```text
python scripts/build_release_zip.py --output dist/kotel.zip --expected-version vX.Y.Z
```

Запускай подходящие проверки после изменений. Не утверждай, что проверка прошла, если команда не запускалась или завершилась ошибкой. Для изменений, зависящих от живого Home Assistant или контроллера, указывай, что локальная проверка не заменяет проверку в реальной установке.

## Правила изменений

- Поддерживай совместимость с Home Assistant и Python согласно `custom_components/kotel/manifest.json` и CI.
- Не меняй идентификаторы сущностей, сохранённые значения состояний, формат данных профилей и их существующие сценарии без явной необходимости; сверяйся с документацией.
- Обновляй переводы согласованно в `strings.json`, `translations/en.json` и `translations/ru.json`; проверяй изменения через `scripts/check_i18n.py`.
- Сохраняй структуру HACS-интеграции в `custom_components/kotel/`. В релизный ZIP попадают файлы этой папки в корне архива, без префикса `custom_components/kotel/`.
- Не помещай реальные логины, пароли, токены и персональные данные в код, тесты, логи, диагностику или примеры.
- Не удаляй и не перезаписывай пользовательские файлы и несвязанные изменения. Не создавай ветки и коммиты, если об этом не попросили.
- Не добавляй в Git кэши, временные файлы и результат сборки `dist/`; исключения поддерживаются в `.gitignore`.
