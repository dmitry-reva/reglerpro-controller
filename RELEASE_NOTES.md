# История версий ReglerPro Controller

Версии перечислены от новых к старым. Дат релизов в файл не внесено. Для каждого релиза указано, что
проверено на живом Home Assistant, а что только юнит-тестами.

**Текущая версия: 1.7.2.**

## Как обновляться

1. Замените файлы интеграции (или обновите через HACS).
2. **Перезапустите Home Assistant.**
3. Если после обновления в интерфейсе видны сырые ключи вместо названий (например, `fan_damper` или
   `rename`), обновите файлы переводов `translations/en.json` и `translations/ru.json` из релиза.

Версии накопительные: обновление с любой версии на последнюю не требует промежуточных шагов.

## Что может удивить после обновления

| С версии | Что изменилось в поведении |
|---|---|
| 1.7.2 | часть числовых полей котла стала «Недоступно» (параметры, которых нет у вашего котла в приложении ReglerPro) |
| 1.7.0 | при добавлении интеграции номер дома можно не вводить: он выбирается из списка; введённый вручную номер должен входить в ваши дома |
| 1.6.2 | профиль климата не применяется, пока климат выключен (ошибка с понятным текстом) |
| 1.6.1 | датчик температуры считается «в сети» 30 минут (раньше 5), контроллер — ещё 10 минут после обрыва связи |
| 1.6.0 | службы доступны, пока загружена интеграция; без загруженной записи отвечают понятной ошибкой |
| 1.5.0 | неверный пароль и неожиданный ответ сервера больше не превращаются в «нет устройств»; запускается повторная авторизация |

## 1.7.2

**Проверено на живом Home Assistant.**

### Добавлено

* Число **Fan damper** (`servo_cooler`): положение заслонки вентилятора, 1–99 %. Доступно только у
  контроллеров, где значение заслонки не равно нулю.
* Число **Sensor temperature correction** (`korect_dt`) у каждого датчика температуры помещения:
  −15…15 °C, шаг 0,5. Значение читается из списка устройств, запись идёт командой `korect_dt` без
  сдвига, как в приложении.

### Изменено

* Числовые поля котла, которые приложение ReglerPro для вашего котла не показывает, отмечаются как
  **«Недоступно»**; их значение остаётся в состоянии, автоматизации могут его читать:
  * параметры шнека (`Auger: interval/run time`) — только у «авто»-котлов;
  * `Fan (min)` — только у остальных котлов;
  * `Temperature correction` и `Burnout time` — только при `korect_20 > 0`;
  * `Fan damper` — только при ненулевом значении.
* Существующие сущности не пересоздаются. На «авто»-котле с нулевой заслонкой недоступны `Fan (min)` и
  `Fan damper` (проверено на живом Home Assistant).
* Всего 116 сущностей в переводах (64 числа, 35 сенсоров, 10 кнопок, 3 списка, 2 текстовых поля,
  переключатель, термостат).

### Известные особенности

* В приложении кнопка «Климат» скрыта для прошивки `201742`; в Home Assistant у такого контроллера
  климатические сущности остаются, но данных не покажут.

## 1.7.0

### Добавлено

* **Проверка входа запросом приложения `login_user`.** Отказ сервера показывается вместе с его
  пояснением («Сервер отклонил вход: …»); текст очищается от разметки и от логина и пароля.
* **Выбор дома из списка** (`get_data_sets`): номер дома при добавлении можно не вводить.
  * один дом выбирается автоматически; несколько домов — шаг «Выбор дома»;
  * введённый вручную номер должен входить в список домов учётной записи («Этого номера дома нет среди
    домов учётной записи: …»);
  * у учётной записи без домов — «У этой учётной записи нет домов»;
  * если список домов получить не удалось (другой вид ответа), остаётся прежний ввод номера вручную.
* Название записи — название дома, если оно известно.

### Изменено

* Повторная авторизация проверяет только логин и пароль (без запроса списка устройств).
* Запрос списка устройств при добавлении выполняется после выбора дома; дубль учётной записи
  отклоняется до этого запроса.

### Новые тексты в переводах

`config.step.select_home`, `config.step.user.data_description`, ошибки `login_rejected`, `no_homes`,
`home_not_found`; обновлён текст `no_home_id`.

Проверено на живом Home Assistant: неверный пароль, вход без номера дома, номер дома не из списка.
Повторная авторизация — проверена ранее (1.5.1).

## 1.6.2

### Изменено

* **Значения профиля климата (режим, температура, расписание, датчик) не записываются, пока
  климат-контроль выключен.** В приложении ReglerPro при выключенном климате доступна только кнопка
  «Включить». Применение сообщает: «климат-контроль выключен: включите его и примените профиль снова».
  Режим при этом не переключается наполовину; значения котла применяются.
* При отсутствии детального ответа контроллера (климат тогда выглядит «выключенным») сообщение называет
  другую причину: «нет актуальных данных климат-контроля».
* В пробном запуске (`dry_run`) такие значения попадают в `skipped` с причиной, без ошибки.
* Параметр службы `force` отключает и эту проверку (описание в переводах обновлено).

Проверено на живом Home Assistant.

## 1.6.1

### Добавлено

* **Повторная проверка записи профиля.** Если значение не подтвердилось, интеграция запрашивает его
  тем же запросом, которым проверяет запись приложение (`get_big_contr_check`), а затем записывает
  неподтверждённые значения ещё один раз.
* **Подробное сообщение кнопки:** «Проблемы: boiler.<параметр> (ожидалось X, получено Y)», число
  повторно записанных значений.

### Изменено (по результатам сверки с приложением ReglerPro)

* Диапазоны `Auger: run time (heating)` и `Auger: run time (maintenance)`: максимум **600** (было 300).
* Датчик температуры «в сети» при `time < 1800` с (было 300 с).
* Контроллер «в сети» при `mqtt_online = 1`, а при `mqtt_online = 0` — ещё 600 с после обрыва связи.
  Сенсор `Connection status` и проверка перед применением профиля используют это правило; исходное
  значение сохранено в атрибуте `mqtt_online`, добавлен `offline_seconds`.
* Один испорченный элемент списка устройств больше не останавливает опрос остальных (в журнал пишется
  одно предупреждение).

Проверено на живом Home Assistant вместе с 1.6.0.

## 1.6.0

### Изменено (внутренняя перестройка по правилам Home Assistant)

* Данные записи хранятся в `entry.runtime_data`.
* Службы регистрируются при загрузке интеграции (`async_setup`), а не при настройке записи. Пока запись
  не загружена, службы отвечают «Интеграция Kotel ещё не загружена» или «Контроллеры Kotel не найдены».
* Задан `PARALLEL_UPDATES`: команды одной платформы выполняются по очереди.
* Платформы объявлены через `Platform`, добавлен `CONFIG_SCHEMA` (настройка только через интерфейс).
* Окно «Register a temperature sensor» у незагруженной записи завершается сообщением «Интеграция не
  загружена».

Проверено на живом Home Assistant: работает полностью.

## 1.5.3

### Изменено

* Ответ запроса `add_device` принимается как идентификатор датчика, только если это цифры (8–20 знаков).
  Текст ошибки сервера больше не показывается как «ID для настройки датчика».
* Идентификатор датчика в профиле записывается, только если такой датчик есть в вашем доме (из списка
  устройств и запроса `get_climat_sensors`); значение другого вида отбрасывается при чтении профиля.

Проверено на живом Home Assistant (регистрация датчика; перенос профилей между контроллерами).

## 1.5.2

### Изменено

* Отсутствие ответа сервера показывается как «Сервер не ответил…», а не «Не удалось подключиться»
  (бывает при несуществующем номере дома у пользователя без домов); текст таймаута больше не пустой.
* **Диагностика** заменяет логин, пароль, номер дома и идентификаторы устройств метками (`<home_id>`,
  `<device-1>` …) везде, в том числе внутри строк и ключей; связи между устройствами сохраняются.

> Файлы диагностики, скачанные из версии 1.5.1 и старше, содержат номер дома и идентификаторы: не
> публикуйте их.

## 1.5.1

### Исправлено

* **Повторная авторизация:** после ввода верного пароля запись теперь перезагружается сама. Раньше, если
  первый опрос закончился отказом, данные оставались недоступными до перезапуска Home Assistant.
* Сообщение об отказе в авторизации больше не повторяет фразу дважды.

### Добавлено

* Точный признак отказа в авторизации: ответ сервера `login_pass_in_db_ok - NO` распознаётся и в ответах на
  команды записи (раньше такая команда считалась выполненной).

## 1.5.0

### Добавлено

* **Повторная авторизация:** если сервер отклонил пароль, Home Assistant предлагает ввести новый;
  запускается сразу при запуске и после двух отказов подряд во время работы.
* Ошибки в окне добавления: «Неверный логин или пароль» (`invalid_auth`) и «Неожиданный ответ» с
  выдержкой из ответа сервера.

### Изменено

* Ответ неожиданного вида при чтении данных больше не превращается в пустой список или словарь: это ошибка.
* Пустой список устройств после успешной работы считается сбоем облака первые три раза (данные не
  стираются).
* Окно добавления использует сессию Home Assistant.

## 1.4.8

### Добавлено

* Шаг **Servers** в «Настроить»: основной и запасные серверы, проверка каждого сервера под вашей учётной
  записью, возможность очистить список запасных (отключить переход) и сохранить без проверки.

### Исправлено

* Сохранение интервала опроса в «Polling and settings» стирало остальные параметры записи.

## 1.4.7

### Добавлено

* **Несколько серверов** (`app.reglerpro.ru` и `web.reglerpro.ru` с общей учётной записью): при сбое
  клиент переходит на другой сервер. Чтение повторяется на другом сервере при сетевой ошибке, таймауте,
  ответе 5xx и ответе не в JSON; команды — только если запрос заведомо не дошёл до сервера
  (команды-переключатели не удваиваются).
* Адрес сервера выбирается из списка или вводится свой.
* В диагностике показаны список серверов и текущий.

### Изменено

* Идентификатор записи не включает адрес сервера: повторное добавление того же логина и дома через другой
  адрес отклоняется (в том числе для записей, созданных раньше).

## 1.4.6

### Исправлено

* **Климат-переключатель:** команды включения и выключения не отправляются, если данные не обновились
  или детальный ответ контроллера не получен (раньше неполные данные могли привести к выключению
  работающего климата).
* Зависимость `file_upload` добавлена в манифест: без неё загрузка файла профилей могла не работать.
* Большие атрибуты сводного сенсора и расписания климата не пишутся в базу истории; сводный сенсор
  `Parameter diagnostics` отключён по умолчанию (у новых установок).
* Схемы служб отклоняют лишние ключи: опечатка в `dry_run` или `verify` больше не приводит к реальной
  записи. Цели служб, кроме «устройство», дают ошибку.
* Профиль перед сохранением обновляет данные контроллера (не сохраняет устаревшие значения).
* Датчик температуры без поля `time` больше не считается «в сети».
* Переключатель Start/Stop: без данных показывает `unknown`; после команды 15 секунд показывает
  ожидаемое состояние, чтобы не «отскакивать».
* Подписи в окнах настроек (тип профиля, способ разрешения конфликтов) стали переводимыми; добавлен
  текст `already_configured`.

## 1.4.1 – 1.4.5

Изменения этих версий по отдельности не фиксировались. По коду 1.4.5 к ним относятся:

* регистрация датчика температуры из окна настроек;
* загрузка файла профилей из окна настроек и экспорт в `www`;
* раздельные профили котла и климата, переименование профилей;
* блокировка записи на контроллер при применении профиля, повторная проверка записанных значений;
* фильтрация расписания по активному режиму.

## 1.4.0

Исправления по результатам первого аудита (подтверждены в коде следующих версий):

* интервал опроса из настроек действительно применяется;
* служба `send_command` зарегистрирована;
* идентификатор записи защищает от дублей;
* пустая запись без устройств больше не создаётся;
* ответ сервера читается и при нестандартном типе содержимого;
* контроллеры опрашиваются параллельно, с изоляцией ошибок;
* единая база сущностей (`KotelEntity`), производитель «ReglerPro», версия прошивки;
* названия сущностей вынесены в переводы;
* современное окно настроек (`OptionsFlow`);
* состояние `mqtt_online` приводится к единому виду;
* ошибки API в числах и переключателе превращаются в понятные ошибки Home Assistant;
* состояние `sost_rab` без данных не выдаётся за «Остановлен»;
* команды климата принимают решение после обновления данных, под блокировкой;
* добавлена диагностика без учётных данных.
