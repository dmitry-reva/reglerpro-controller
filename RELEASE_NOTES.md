# ReglerPro Controller — релиз 1.3.0

**Дата:** 2026-10-22
**Тип:** функциональное обновление
**Требования:** Home Assistant 2026.3.0 и новее
**После обновления:** перезапуск Home Assistant

Главное в релизе — **профили настроек**: наборы значений («Зима», «Лето», «Отпуск») можно сохранять, переключать вручную, по расписанию и по событиям, отменять и переносить между установками через файл.

---

## ✨ Что нового в 1.3.0

### Профили настроек

- **Сохранение любого числа наборов** (до 20 на контроллер). Профили хранятся **отдельно для каждого контроллера** в `.storage/kotel.profiles`; файл входит в резервные копии Home Assistant.
- **Состав профиля.** По умолчанию сохраняются **только настройки котла** (11 параметров). При необходимости добавляются: режим и целевая температура климата, расписание, датчик климат-контроля. Старт/стоп и включение климата в профили не входят.
- **Переключение:** вручную (список, кнопки, дашборд), по расписанию (время, дни недели, сезон) и по событиям (присутствие, уличная температура, календарь). Готовые примеры автоматизаций — в [docs/PROFILES.md](./docs/PROFILES.md).
- **Безопасное применение:**
  - записывается только разница между профилем и текущими значениями;
  - значения вне допустимых диапазонов не записываются и попадают в отчёт;
  - время периодов расписания пишется в порядке, при котором правило «P1 < P2 < P3 < P4» не нарушается ни на одном шаге;
  - если контроллер не в сети, применение блокируется;
  - команды одного контроллера выполняются строго по очереди;
  - результат проверяется повторным чтением (до 20 секунд);
  - перед записью сохраняется состояние для **отката**.
- **Экспорт и импорт в файл (JSON)** с выбором профилей. Файл не содержит логина, пароля и адресов серверов. При конфликте имён: добавить номер, заменить или пропустить. Работает через меню «Настроить» интеграции и через службы.
- **Новые сущности** (на каждый контроллер):

  | Сущность | Назначение |
  |---|---|
  | `select` «Профиль» | выбор профиля |
  | `text` «Имя нового профиля» | имя для сохранения |
  | `button` «Сохранить профиль» | сохранить под введённым именем |
  | `button` «Обновить профиль» | перезаписать выбранный профиль текущими значениями |
  | `button` «Применить профиль» | записать выбранный профиль в контроллер |
  | `button` «Отменить применение» | вернуть значения до применения (доступна только после применения) |
  | `sensor` «Активный профиль» | имя профиля, совпадающего с текущими настройками, либо `изменён` / `нет профилей` |

- **Новые службы:** `kotel.save_profile`, `apply_profile` (с `dry_run`), `undo_apply`, `rename_profile`, `delete_profile`, `list_profiles`, `export_profiles`, `import_profiles`. Службы `apply_profile`, `save_profile`, `undo_apply`, `export_profiles` и `import_profiles` возвращают отчёт (`response_variable`).
- **Новые события:** `kotel_profile_saved`, `kotel_profile_applied`.

### Интерфейс интеграции

- **Меню «Настроить»** теперь содержит пункты: *Опрос и параметры*, *Экспорт профилей в файл*, *Импорт профилей из файла*, *Удалить профили*.
- Добавлены **переводы** (`translations/ru.json`, `translations/en.json`, `strings.json`) для форм подключения и настройки.
- Новые платформы: `text`, `button`.

### Дашборд

- В пример дашборда добавлена карточка **«Профили настроек»** (активный профиль, выбор, применение, откат, сохранение).

## ⬆️ Обновление

### С версии 1.2.x

1. Рекомендуется создать резервную копию Home Assistant.
2. Обновите интеграцию через HACS либо замените файлы в `custom_components/kotel/` (полный список — в [docs/INSTALLATION.md](./docs/INSTALLATION.md)).
3. Перезапустите Home Assistant.
4. Появятся новые сущности профилей. Существующие сущности, автоматизации и дашборды не затрагиваются.

Если у вас уже есть собственные `translations/`, объедините их с поставляемыми: разделы `config` и `options` описаны полностью.

### С версии 1.1.x

Кроме шагов выше учтите изменения версий 1.2.0 и 1.2.1 (см. ниже), в частности удаление 8 сенсоров и замену значений `0` / `1` на «нет» / «да» у бинарных сенсоров.

## ⚠️ Известные особенности

- **Интервал опроса** фиксирован (30 секунд): параметр `scan_interval` из окна настроек сохраняется, но пока не применяется.
- **Служба `kotel.send_command`** описана в `services.yaml`, но не зарегистрирована.
- **Порядок записи уставок.** Неизвестно, требует ли контроллер, чтобы минимальная уставка была меньше максимальной; при значительном сдвиге обеих уставок рекомендуется сначала выполнить `apply_profile` с `dry_run: true`.
- **Расписания 5/2 и 4/1/2.** Ключи этих наборов на сервере появляются после первой записи; поведение сервера при записи «с нуля» проверяется.
- **Задержка подтверждения.** Значения настроек котла приходят от устройства с задержкой; при медленной связи параметры могут попасть в список «не подтверждено», хотя уже применены.
- **Новые устройства**, добавленные в облако после запуска, появляются после перезагрузки интеграции.
- Смысл значений аварий и ошибок выведен из названий параметров; они отображаются как «нет» / «да» (без `binary_sensor`).
- Индикаторы «ШНЕК» и «НАСОС» в примере дашборда не заполняются: прошивка не отдаёт отдельного признака их работы.
- Файл профилей остаётся в `.storage/` при удалении интеграции из интерфейса.

## 📋 План

- Аварийные параметры как `binary_sensor` (`device_class=PROBLEM`).
- Применение `scan_interval` из окна настроек.
- Регистрация службы `send_command` либо удаление её описания.
- `resp.json(content_type=None)` в `api.py` для серверов, отдающих другой `Content-Type`.
- `has_entity_name` для корректных имён при нескольких контроллерах.
- Выбор областей (климат, расписание) при сохранении профиля кнопкой в интерфейсе.

# История версий

## 1.2.1

- **Термостат показывает текущую температуру с десятыми.** Контроллер отдаёт температуру выбранного датчика целой (`sensor_temp = "24"`), поэтому используется значение самого датчика из списка устройств; при его отсутствии прежнее. Точность термостата 0,1 °C (шаг целевой температуры 0,5 °C).
- **Бинарные сенсоры отображаются как «нет» / «да»** вместо `0` / `1` (тип сенсора — перечисление; исходное число в атрибуте `value`). Затронуты: вентилятор включён, ошибки датчиков воды и шнека, авария шнека, тревога по воде, ошибка симистора, автореверс шнека, реверс сейчас, выносной датчик используется, «Климат: включён», «Климат: датчик выбран».
- В дашборде добавлен виджет термостата, условия индикаторов и аварийной плашки переведены на «да» / «нет».

> ⚠️ **Миграция.** Автоматизации, шаблоны и карточки, которые сравнивали состояния этих сенсоров с `"0"` и `"1"`, замените на `"нет"` и `"да"`. «Статус подключения» (`online` / `offline`) не менялся.

## 1.2.0

### Климат-контроль

- **Термостат (`climate`)**: режимы `Выкл`, `Нагрев` (постоянная температура), `Авто` (расписание); пресеты «Расписание 7/7», «Расписание 5/2», «Расписание 4/1/2»; целевая температура 5–40 °C с шагом 0,5 (в режиме расписания только чтение); действие по `tstatNow` (`0` — нагрев, `1` — охлаждение).
- **Выбор датчика климат-контроля** (`select`).
- **48 полей расписания** (`number`, категория «Конфигурация»): время начала и температура для 4 периодов в 6 наборах. Границы времени зависят от соседних периодов.
- Команда `climat_on_off` на сервере — переключатель, поэтому перед включением и выключением данные обновляются и команда отправляется только при необходимости.
- Описание протокола: [docs/CLIMATE.md](./docs/CLIMATE.md).

### Диагностика

- Диагностические сенсоры по параметрам, которые отдаёт прошивка: версия, вентилятор, аварии и ошибки, шнек, климат, выносной датчик, значения климат-контроля.
- Сводный сенсор **«Диагностика параметров»** с атрибутами `params`, `params_raw`, `params_format`, `climate`, `tstatArr`, `tempUstNowTstate`, `raw_keys`.

### Удалено

Интеграция больше не создаёт 8 сенсоров, по которым прошивка не отдаёт данных; те же параметры доступны как `number`-сущности. Устаревшие записи удаляются из реестра автоматически.

| Параметр | Сенсор |
|---|---|
| `vent_max`, `vent_min` | Вентилятор (max), Вентилятор (min) |
| `nasos_t` | Температура насоса |
| `produv_time`, `produv_interval` | Время продувки, Интервал продувки |
| `time_ugas` | Время угасания |
| `korect_` | Коррекция температуры |
| `servo_cooler` | Заслонка вентилятора |

Если автоматизации или дашборды ссылались на эти `sensor.*`, замените их на `number.*`.

### Исправления

- `sensor.py`: класс `KotelClimateModeSensor` был вложен в другой класс, из-за чего платформа `sensor` не загружалась (`IndentationError`).
- Сенсор `tstatNow`: убраны несуществующий `SensorDeviceClass.STATE`, неподдерживаемый `extra_state_attributes` и словарь вместо строки в `icon`.
- Парсер `params`: дробные значения (`45.5`) больше не превращаются в `0`; отсутствующий `tstatNow` даёт `None`, а не «нагрев»; при отсутствии `korect_20` параметр `korect_` не равен `-20`; проверяется, что JSON — это список; порядок определения формата совпадает с `functions.js`.
- `is_kotel_auto` и `sost_rab_text` не падают на `None` и строковых значениях.
- Флаги климат-контроля из API (`"0"`, `"false"`) разбираются корректно.
- Пустой ответ `get_big_contr` больше не затирает данные контроллера: используется элемент из `get_all_dev`.

## 1.1.0

Базовая версия: сенсоры контроллера и датчиков, переключатель старт/стоп, регуляторы настроек (`number`), опрос облака `app.reglerpro.ru`.
